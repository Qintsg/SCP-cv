## 四种尺寸不要混用

- Windows桌面尺寸决定播放器窗口落位。
- 输入主组播尺寸决定墙面源裁剪及电视610D源尺寸。
- RTSP/RTMP chn0、chn1是预览通道，可能与主组播不同，不能直接覆盖控制帧。
- 50个墙节点目的矩形及电视输出模式独立。现有墙10×5、19200×5400工程参数对应节点1920×1080；没有当前实时输出尺寸回读，不能因D4为4K一起改节点到4K。

## 更换信号或修改分辨率之后

在能访问现场网络的电脑上运行：

```powershell
node tools/input-resolution/probe.cjs
```

工具只查固定31路输入4830，每路最多1500ms及65536字节，串行无重试。只发原客户端固定12字节611A，不拉视频、不发映射、不修改配置，不接受自定义目标参数。输出逐路JSON，离线/畸形响应不会得到虚构尺寸；回读未知校验算法不称CRC已验。此工具有Node环境要求，普通网页观看预览仍无需Node/FFmpeg。

确认主组播地址、端口及尺寸，必要时被动取SPS交叉核验，再通过既有`VideoWall:Inputs`受信配置修改尺寸并重启服务。目录是日期明确的默认快照，不会后台自动扫描或热改共享配置。同一IP的窗口别名及IP键必须使用一致的完整描述，冲突会在首包前拒绝，不能只加一条与原窗口配置矛盾的IP记录。

未知84仍可出现在目录和预览中，但不能未经确认下发墙或电视；有可靠设备参数后可显式配置。预案按完整帧指纹去重，尺寸变化必须重发；名称变化不造成重复发送，手动仍可重发。
