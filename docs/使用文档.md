# SCP-cv 使用文档

文稿安全门禁按声明格式与可解析包内容检查，不能通过把OOXML文稿改名为.ppt绕过外链拒绝。原件保留；已知危险包准备失败需查看原因，不盲目重试。宏执行/自动更新禁止不表示所有含宏/加密旧格式都已在预检识别，当前验证边界见[LibreOffice运行指南](libreoffice-playback.md)。
当前不支持文稿密码输入；加密动态候选拒绝后保留旧源。加密ODP静态加载终止已可在无模型/输出且正常引擎退出后明确报告失败；导出或退出未确认仍不确定，请勿把它当完成或反复重试，旧uncertain不变，排查见[加载终止记录](../specs/008-libreoffice-playback/verification/load-rejection-20261003.md)。

## 1. 系统说明

SCP-cv 的控制端由同一套 Vue 页面提供，支持浏览器、Windows Electron 和 Android Capacitor。Supervisor管理两个大屏PlayerWorker、AudioWorker与MediaMTX；文稿播放由Player按需创建独立LibreOffice侧车，转换由ControlHost独立执行。控制桌面照旧，两台小电视仅保留电源控制。

控制端在线只表示 REST/SSE 链路可用；只有运行时状态显示对应 Worker 在线时，才代表命令有实际画面执行端。

## 2. 环境准备

需要Windows 10/11 x64、.NET SDK 10.0.400、Framework 4.8运行时/targeting pack、Node.js 22+、pnpm 11、VLC/libVLC与MediaMTX。PPT/PPTX的播放和转换均使用带官方.NET互操作组件的LibreOffice，不启动PowerPoint。Node依赖必须使用pnpm，仓库已配置教育网联合镜像站。

```powershell
dotnet restore runtime-dotnet/ScpCv.sln --locked-mode
dotnet build runtime-dotnet/ScpCv.sln -c Release --no-restore
pnpm install
pnpm --prefix frontend install
```

第三方运行时路径：

- `tools/third_party/mediamtx/mediamtx.exe`
- `tools/third_party/vlc/runtime/`，或 `C:\Program Files\VideoLAN\VLC`
- LibreOffice官方Windows x64安装（本机验证26.8.0.3）；路径和能力见[文稿运行指南](libreoffice-playback.md)

## 3. 配置

ControlHost 默认配置位于 `runtime-dotnet/src/ScpCv.ControlHost/appsettings.json`。常用项：

- `SafetyMode`：`Simulation` 或 `Hardware`。
- `DataRoot:RootPath`：新 .NET 数据目录，默认 `data/dotnet`。
- `Authentication:AllowedOrigins`：允许带凭据访问的精确 Origin。
- `AllowedHosts`：允许的 Host 列表。
- `Devices:Endpoints`：拼接屏与电视电源控制地址。
- `Media:AllowedLocalRoots`：允许注册为本机媒体源的根目录。
- `BigScreenOutputs`：两块大屏的明确显示器绑定；目标缺失时播放器拒绝回退到控制桌面。

前端复制 `frontend/.env.example` 为 `frontend/.env`，按实际主机修改 `VITE_BACKEND_TARGET`。Web 开发可以使用明确的本机 HTTP 地址；Electron/Android 常规包应连接设备信任的 HTTPS 主机。

开发账号口令通过 `SCP_CV_DEVELOPMENT_PASSWORD` 或 `run-headless.ps1 -DevelopmentPasswordFile` 提供。不要把口令提交到仓库或放进进程命令行。

## 4. 启动

### 4.1 Simulation 开发模式

```powershell
dotnet run --project runtime-dotnet/src/ScpCv.ControlHost -- `
  --SafetyMode=Simulation `
  --urls=http://127.0.0.1:18000 `
  --DataRoot=.validation/dotnet

pnpm --prefix frontend run dev:web
```

Simulation 不访问显示器、系统音量、设备电源或视频墙，也不会启动实际播放器进程。

### 4.2 Hardware 播放模式

在 Windows 交互桌面中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File runtime-dotnet/scripts/run-headless.ps1 `
  -SafetyMode Hardware `
  -StartWorkers `
  -Detach `
  -DataRoot data/dotnet `
  -ListenUrls https://localhost:18443 `
  -AllowedHosts 'localhost;127.0.0.1' `
  -AllowedOrigins 'https://localhost' `
  -DevelopmentPasswordFile '<口令文件>'
```

停止：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File runtime-dotnet/scripts/run-headless.ps1 `
  -Stop `
  -DataRoot data/dotnet
```

非交互 Session 0 无法可靠访问物理显示器和 Office 窗口。远程部署应按 `docs/qa/003-workstation-runbook.md` 把运行时交给当前登录用户的交互桌面。

运行组停止会等待自有成员退出确认，再清除未执行的旧命令，不关闭Windows或控制台服务。
重启先完成停止，再启动新组；如果停止失败，界面会报错且不会继续启动。
旧播放意图不会自动恢复，停止成功后pending为空也不代表最后实际源已被观测为空。
若提示启停操作正在进行，另一个请求已被拒绝且不会稍后自动执行；先等待并核对已有操作结果。

## 5. 控制台操作

### 5.1 媒体源

- 上传文件：文件内容上传到播放主机的 `DataRoot/media/`；在页面选中“PPT文件”等文件夹时，原件保存到对应实体目录，如 `media/PPT文件/b.pptx`。同名文件自动追加序号，不覆盖旧文件。
- 上传请求上限为1GiB，文件内容、表单字段和multipart开销合计计算；超过上限返回413 `upload_too_large`。畸形表单明确拒绝，不登记半份媒体。此上限只作用于上传接口，不放宽普通JSON请求；代理或IIS部署还须核其自身限制。
- 添加本机路径：路径属于播放主机，不是手机或控制电脑的本地路径。
- 添加网页源：由 PlayerWorker 的 WebView2 打开。
- 直播流：在“添加源 → 直播流”选择 RTSP、SRT 或自定义 IP 媒体流并填写地址；登记后会显示“待验证”，不等于已连通。到窗口 1/2 打开后，以实际画面和播放错误判断是否可用。地址可在源编辑抽屉修改，仅影响下次打开。MediaMTX 可用于现场推拉流，但也可登记其它可达流地址；不接受在地址里内嵌用户名/密码。
- PPT/PPTX：原件保留，后台由独立LibreOffice实例准备PNG和只含图片的静态PDF。默认动态放映不受页图排队或失败阻断；静态回退必须手动选择且已准备。文字适配默认关闭，适配版静态制品需单独准备；没有PowerPoint实验性入口。PDF原源继续PDF播放。
- 文件夹：可创建中文名称和子目录、重命名、移动文件夹或单个源。实体文件随之移动，下载内容不变；播放中或转换中的原件不能移动。原件被占用或没有移动权限时会明确返回“移动未生效”，保留原路径和内容。删除文件夹默认把原件搬回媒体根目录，遇到未登记文件会拒绝；勾选“同时删除内容”才永久删除子树内源及实体目录。旧日期路径不会自动批量迁移，只有显式移动时才改写。
- 删除单个源：播放/转换中、原件被占用或只读时会明确拒绝，源记录和原件仍保留。若提示 `media_cleanup_pending`，可能已提交删除但隔离区清理未完成，或提交结果尚未确认；页面会重新同步列表，维护人员须按提示检查隔离清单，不能当作完全删除成功。
- 错误提示需手动关闭；反复触发相同且无操作按钮的错误时只保留一条，避免遮挡手机页面。不同错误及带“重试”等按钮的提示仍分别保留。

媒体源列表中的“可用”只表示可以尝试打开。PPT/PPTX 原件存在且已登记摘要时，即使静态制品仍排队或失败，默认模式仍为 LibreOffice；不保证依赖、文稿兼容性或真实出画。API 的 `playback_mode` 在媒体源上是默认选择，实际播出以会话观测为准。原排版页图状态和页数不代表文字适配版已准备；两版分别保存在 `slide_images/static_pdf` 与 `fitted_slide_images/fitted_static_pdf` 元数据中。显式静态 OPEN 会检查所选布局，缺失时拒绝打开、不借用另一版；控制台预览另按实际布局及独立制品门禁确认，不以OPEN受理冒充预览就绪。历史 `powerpoint` 值仅用于只读兼容，新打开不接受；旧 PowerPoint 设置和应急入口均明确退役。

选源、上传并打开、媒体库打开或播放背景音乐后，“已提交请求”只确认后端受理，不能据此判断已出画或出声；后续仍看实际会话、播放状态及现场画面。

控制页的“当前输出参考”和专注页预览按已观测的实际文稿及文字布局显示。切源失败时仍显示原实际文稿，不借失败的新源或另一布局缩略图；实际源/布局未知时明确显示未确认。“刷新预览”只读取静态参考图，不重开或控制 LibreOffice；预览未准备不会修改原生播放状态。列表默认缩略图只提供有效原排版制品，适配版需按实际布局取图。丢页后可显式重新准备，`uncertain` 仍先核查。

设置中的“演示文稿播放”逐项显示本次运行依赖检查及原因，可点击“重新检查”。“静态检查通过”仅表示允许尝试，不证明文稿或画面成功；缺组件请按建议补装官方依赖。网络失败、响应无效或切换播放主机后保持“待检查”，不沿用旧结果。运行机不需要开发SDK或Framework targeting pack。

“跳页”输入完整的十进制正整数，`2a`、小数、空值等会提示页码无效，不发送导航。已有“跳转”按钮可用键盘激活；输入框本身未新增Enter快捷入口。导航请求受理不等于实际换页，动画步后页码不变也不等于动画已结束。
“已受理”状态会在指令排队或播放器执行中保留，终态后才转到下一条或消失；消失不表示动画/视频已结束。快速连续动画推进尚有步序不确定的实测缺口，不要把请求次数当已经播放的效果数。
动画中“下一步”按快速完成当前动画后继续推进处理；基础样例已通过，无动画页直接换页。要求最后一页动画耗尽后保持画面，并提示“当前已是最后一页”，不进入结束黑屏。控制页/专注页只查询本次命令的持久终态，不用页码或HTTP受理猜测；无主序末页已接原生无操作并在D4有限小窗验证。带动画的末页保护仍在接入，当前版本不能作为最终现场版；剩余动画不禁用，完整闭环待实机验证。
离开控制页后旧动画请求的错误不会在后续页面弹出；已经受理的操作并未因此撤销。当前页失败仍明确提示，请核查后显式操作，不自动重放。
切源、同源重开、倒退、后续客户端操作或离开页面会使旧命令提示失效。终态查询失败或读取安排范围（35秒，单次仍沿既有10秒HTTP预算）结束后仍未取得终态时提示未确认，不自动重发；这不是动画完成计时器，也不撤销已经入队的操作。
本机两独占实例已分别验证窗口1/2各十轮100控制和20次异源切换，有限标题/字幕与保持端内容未串扰，正常关闭通过。这不是完整播放器、媒体时钟、满幅或长时间现场验收，仍不要将当前草稿直接用于现场。
切换文稿时若同时提示旧资源关闭与候选清理未确认，结果为“不确定”，候选未被发布；最后记录的实际源不保证当前画面仍在。先核查自有进程/窗口和关闭结果，再显式操作，不自动重试。
若旧文稿已关闭、候选切入失败但也确认释放，显示明确空输出错误，翻页/跳页及专注页方向键不可用；重新选择源打开后可恢复。若候选清理仍未确认，普通控制暂时隔离，关闭与退出也不能假成功，请按维护说明核查并重启自有运行组，不自动重复原生动作。

项目自有LibreOffice实例的临时配置关闭自动更新，不影响平时打开的LibreOffice或其更新设置；安装升级仍由维护者管理。启动环境中的强制更新测试覆盖会被明确拒绝，不能用延长等待或盲重开掩盖。

### 5.2 两个播放窗口与大屏信号映射

2026-10-09紧凑界面、美化及63/64配置已部署D4；刷新[控制台](http://192.168.5.194:5173/)即可使用。此次只读部署核验未应用布局，实体墙面不会因配置更新自动切换；详见[部署记录](deployments/20261009-d4-compact.md)。

窗口 1、2 对应大屏两块输出。小电视不再接收媒体窗口，但设置页仍保留其电源开关；电视协议只有 toggle，不提供可靠状态读回。

首页和设置→运行设置的“大屏布局”是一个紧凑交互块：选择单屏或双屏，再在全屏区域或左右区域选择窗口1、窗口2、IP81；不罗列12个组合按钮。左右可选同一输入，单/双屏往返保留各自选择，也支持仅映射一侧。布局名称在折叠的“布局选项”中。

屏幕边框和细拼接网格只表示布局配置，不是实时画面。标题旁的“草稿已保存”仅表示草稿状态；下方发送状态独立显示。留空区域使用淡化样式但仍可选源，保存为次要按钮、应用为主要按钮；支持浅色/深色主题和键盘焦点。

窗口1/2对应D4的`192.168.5.63/64`，组播`224.1.1.63/64`，不使用旧D2的55/56。IP81是现场`192.168.5.81`输入，不是控制电脑。先保存草稿再显式应用，选源不自动下发；编辑后需重新保存，另一客户端改稿时旧版本拒绝。其他入口保留两个旧快捷预设，但同样使用当前D4绑定。自定义IP须由主机登记设备兼容流，未登记只预览。页面区分模拟、已发送但实体未确认和不确定，不把成功响应当出画；失败后先核对墙面和日志。详见[大屏映射指南](video-wall-mapping.md)。

### 5.3 背景音频

背景音乐由独立 AudioWorker 播放，不占用两个大屏窗口。播放列表支持立即播放、循环、音量和静音。

点击播放后的“已提交播放请求”只表示后端受理，不能据此判断已经出声；播放状态和进度以播放器后续回报为准。
切换主机后，旧主机请求的迟到通知不会显示在新主机页面。
离开背景音乐页后，该页在途播放或刷新的迟到通知不会出现在其它页面；已经提交的请求仍由后端处理，不会取消或自动重发。
连续操作时，较早请求结束不会提前解除较新请求的等待标记。

播放中或暂停且已取得有效时长时，可以拖动进度条或用方向键定位；手机上也显示当前时间和总时长。
停止、加载、错误、空源或未知时长时不能定位。提交目标只是请求，实际位置由播放器后续状态更新确认。
换曲会丢弃尚未发出的旧定位缓冲，切换主机不会把旧主机的音量缓冲发送到新主机。

“列表循环”开启时按列表顺序播放，末曲结束后回首曲；关闭时末曲结束后停止并保留末曲。
中间曲仍自动推进，不会原地循环本曲；手动上一首/下一首保留回环。

### 5.4 预案

预案目标有“未设置、清空、指定源”三态。未设置保持窗口现状，清空停止显示，指定源打开原绑定媒体。物理音量和设备副作用是否已真正执行，以 Worker/硬件状态和日志为准，不以 HTTP 受理响应为准。

预案指定系统音量时，Hardware 模式先下发墙面（若指定）、再设置音量并保留当前系统静音，
成功读回后才保存运行态并派发媒体命令。“未设置/清空”系统音量不改变声卡。
若音量或状态提交失败，界面会说明已发生的动作；不要直接重复激活，以免重复实体操作。
先核对实际墙面/系统音量与运行态，再决定恢复或重试。

## 8. 常见问题

### 前端能打开但接口失败

检查 `VITE_BACKEND_TARGET`、ControlHost 监听地址、`AllowedHosts`、`Authentication:AllowedOrigins`、证书信任与防火墙。切换主机后客户端会清理旧会话，需要重新登录。

### 播放器离线

检查 ControlHost 日志、Supervisor 状态、Named Pipe 登记、Worker heartbeat 和交互桌面。运行组中任一关键输出进程退出会触发整组协作停止。

选中源不等于已播出：“正在播出／直播中”只在播放器在线且实际状态为 playing 时显示。离线时选源、上传并打开和视频进度禁止提交；恢复网络后不会自动补发旧的待发进度，需重新操作。已受理的 HTTP 请求不承诺撤销。

### PPT 无法播放

若自定义放映重复引用同一页，当前动态导航会明确拒绝；请用不重复页序，或选择静态页图/PDF。
这是自定义页序限制，不是一概禁止重复动画；静态按标准文稿页序显示、不保留动画/媒体。

若提示“主动画序列重复播放”暂不支持，可取消这种重复，或在选源面板明确选择静态逐页图片/PDF。
该限制保护当前LibreOffice版本稳定性，原文件不改，普通动画不受这项限制；静态不保留动画/多媒体。
源列表“当前输出”标最后实际报告的源，“请求中/请求失败”是另一请求，切换失败后不要据请求名判断大屏已换画面。
离线明示“最后报告”，不是仍在播出的证明。

先区分动态原件与静态准备：queued/running只表示静态制品在准备，missing/failed可明确重试；missing不表示原件丢失。uncertain需核查自有LibreOffice实例、暂存区和日志，不能盲重放。长时间排队检查Framework宿主与官方互操作组件；转换不等待两块大屏空闲。具体限制见[文稿运行指南](libreoffice-playback.md)。

### 直播无法播放

检查 MediaMTX 进程、8890/8554/9997 端口、流标识、VLC runtime 与网络策略。RTSP 会话即使显示 `playing`，也须结合实际画面和独立解码告警判断；曾有写队列设为 8 导致丢帧和空白的实机案例，当前配置为 512。SRT publish latency 使用微秒，播放器 read latency 使用毫秒，不要混用。

网页屏幕共享是另一项正在开发的能力：目标是原生选择器直接投到窗口1/2，不需额外推流。当前只完成后端信令/授权，正式网页入口与Player接入尚未完成、未部署D4；普通LAN HTTP不能采集屏幕。不要把已受理或本机原型当作大屏已出画，详见[屏幕共享进度与边界](screen-sharing.md)。

### 拼接屏模式未变化

检查 50 个节点 `192.168.5.101–150:4830` 的连通性与 ControlHost 视频墙日志。拼接屏电源 `192.168.5.10:8889` 与画面映射不是同一条链路。
