# 设备回读、远程输入与语音解析

相关资料：[成帧](03-device-framing-and-crypto.md)、[业务](04-wall-matrix-audio.md)、[KVM与辅助服务](06-kvm-and-auxiliary-services.md)。所有偏移从帧首0起算；以下整数除特别标注外均为大端。

## 识别规则

同一个命令需要按首标记、控制字节、长度和尾标记一起识别。例如 `FCFD6102` 至少有10、11、22字节payload三种解析入口。请求构造也会使用FCFD，不能用首标记单独判断方向。

常见结构是8字节首部、N字节payload、2字节未检查的校验位置、2字节包尾，完整长度为N+12。固定解析器34类已核对基本向量、payload字节差分、半包及环绕；99个输出字段的1193次独立解码比较全部一致。

这34类对损坏校验位置的合成样例均返回成功。这个结果只适用于这些原客户端解析器，不能证明发送端可以删除校验，也不能说明设备已执行某个动作。完整结构与输出对应关系保存在 [reply-fields.csv](catalogs/reply-fields.csv) 和 [固定回读样例](samples/reply-field-verification.json)。

## 墙面窗口回读

`FCFD 6102 0000 0016`（N=22、完整34字节）由 `0x00664B30` 解析：

| 偏移 | 字段 | 原客户端用途 |
| --- | --- | --- |
| 8 | 窗口标识u16 | `nWinID` |
| 10 | IPv4 | 输入流地址 |
| 14 | 端口u16 | 输入流端口 |
| 16、18 | x、yu16 | 节点矩形左上点 |
| 20、22 | width、heightu16 | 矩形尺寸 |
| 24 | u16 | `nZValue` |
| 26 | u16 | `nTotalCount` |
| 28 | u16 | `nScreenID` |
| 30 | 2字节 | 原解析器未检查的校验位置 |
| 32 | `FE FF` | 包尾 |

`0x007071D0` 将这些输出传给 `si_JointInputRecall`，再追加接收连接自身的设备IP。设备IP不在本帧的payload中。Qt的QRect存储为 `[x,y,x+width-1,y+height-1]`，不能把输出内存的第三、第四整数当成宽高。

这个回读布局与45字节下发映射不同。回读的 `nZValue/nTotalCount/nScreenID` 不能直接拿同一偏移复制到下发帧；下发字段的客户端来源见04。

## 变长名称与配置

`0x00669DF0/0x0066A240` 分别解析 `FCFC2100/FCFC2200`，payload为：

```text
IPv4[4] port:be16 name_length:u8 name[name_length]
```

N=`7+name_length`，完整长度N+12，尾 `FD FD`。名称逐字节追加到QString。反编译器原先漏掉了第六个输出参数；按 `0x0070B360` 的真实调用与原追加指令补齐后，`abc/xy` 非空名称的完整、半包、环绕都核对成功。

`0x0066AC00` 是 `FCFC2300` 的另一变长入口，payload为 `lenA:u8 textA[lenA] lenB:u8 textB[lenB]`，N=`2+lenA+lenB`，尾 `FD FD`。它与上一节N=8的2300入口是不同解析路径。两个字符串输出也由真实调用方补齐，非空`a/b`向量已验证。

## UDP63430远程输入

以下两条的偏移6～7表示**完整消息长度**，高字节固定为0，不能套N+12。

固定鼠标输入由 `0x0066AE30` 读取：

```text
FB FC 2A 01 00 00 00 14 00 01
event:u8 button:u8 x:be16 y:be16 unchecked[2] FD FE
```

共20字节。`0x007125C0` 用x/y寻找 `QApplication::widgetAt` 的控件，构造QMouseEvent，再通知Qt对象；这是客户端界面事件分派，不是Windows键盘扫描码通道。

登录／来源资料由 `0x0066B000` 读取：

```text
FB FC 2A 01 00 00 00 total:u8 00 03
IPv4_A[4] IPv4_B[4]
username_len:u8 username[username_len]
password_len:u8 password[password_len] unchecked[2] FD FE
```

完整长度为 `24+username_len+password_len`。本版本只在扫描偏移大于24后判断包尾，因此非常短的两段文本并不保证被正常识别。

发现一个原客户端问题：IPv4读取使用环形索引，但用户名和密码的复制使用环形数组固定起点附近的地址，没有加当前消息读位置。合成向量在读位置0得到`u/demo`，跨末尾时返回成功但得到`o/空串`。资料保留了这个差异，没有把“解析成功”写成“所有字段正确”。

关闭输入窗口的固定消息为 `FBFC2A010000000E00040000FDFE`，共14字节，由 `0x0066C020` 识别，接收调度调用QWidget关闭路径。没有在本机注入上述事件。

## TCP8099语音返回

| 消息 | payload | 包尾／入口 |
| --- | --- | --- |
| `FAFB2200` | 三段 `len:u8 text[len]` | `FCFD`，`66C660` |
| `FAFB2201` | 空payload | `FCFD`，`66CC40` |
| `FAFB2202` | N字节文本，没有额外的内层长度 | `FCFD`，`66CD50` |

2200与2202在首部只允许长度高字节为0，完整长度N+12；文本经字节数组和 `fromAscii_helper` 转成QString。2200的三段原始输出按下划线拼成日志后，传入 `0x004170C0` 执行工程命令分派；2201没有文本输出。三种路径的ASCII合成向量、半包和环绕已验证。真实中文文本的编码仍要按识别服务与本机Qt配置核对。

服务端的识别算法、账号和内部状态按用户要求不分析。客户端收到文本后匹配工程／宏命令的行为见10。
