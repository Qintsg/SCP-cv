# 墙面、矩阵与音频控制

相关资料：[成帧规则](03-device-framing-and-crypto.md)、[状态 JSON](07-text-control-and-project-transfer.md)、[旧帧复核](08-audit-and-verification.md)。

## 窗口映射 `61 02`

原始构造函数为 `0x0066DD60`，返回 45 字节。下表偏移从 0 起算；所有 `u16` 使用大端。

| 偏移 | 大小 | 字段 | 当前证据 |
| --- | --- | --- | --- |
| 0 | 2 | `FB FC` | 原代码差分 |
| 2 | 2 | `61 02` | 原代码差分 |
| 4、5 | 各 1 | 两个控制字节 | 原函数分别赋值；既有预设为零 |
| 6 | 2 | payload 长度 `33` | 原代码差分 |
| 8 | 2 | 窗口标识 | 原代码差分 |
| 10 | 4 | 输入 `GroupIp` 的 IPv4 字节 | 原代码差分 |
| 14 | 2 | 输入流端口 | 原代码差分 |
| 16、18 | 各 2 | 目标节点内 x、y | 原代码差分 |
| 20、22 | 各 2 | 目标节点内宽、高 | 原代码差分 |
| 24 | 2 | `WindowLevel`，窗口层级／第二分配标识 | 创建与状态序列化调用链确认，见下文 |
| 26、28 | 各 2 | 输入源裁剪 x、y | 原代码差分 |
| 30、32 | 各 2 | 输入源裁剪宽、高 | 原代码差分 |
| 34 | 2 | A：调用方提供的窗口总数 | 创建路径取场景窗口列表数量；既有预设为9 |
| 36 | 2 | B：本窗口跨屏分片计数 | 遍历相交屏幕时递增；既有预设为1 |
| 38 | 2 | C：屏幕索引 | 创建路径使用 `row*columns+column+1`；既有预设为1 |
| 40 | 1 | 模式字节 | 既有预设为 1；不参加此帧校验 |
| 41 | 2 | 累加校验 | `sum(packet[2:40]) & 0xFFFF` |
| 43 | 2 | `FD FE` | 原代码差分 |

原函数接受目标与源矩形的**左上坐标、包含最后像素的右下坐标**，然后计算 `right-left+1`、`bottom-top+1`。例如宽高 1920×1080 对应 `(0,0)-(1919,1079)`；传入 `(1920,1080)` 作为右下点会多出一行和一列。

原函数参数顺序，省略 `this`：

```text
output, windowId, GroupIp(QString), port,
dstLeft, dstTop, dstRight, dstBottom,
srcLeft, srcTop, srcRight, srcBottom,
secondId, B, A, C, marker, headerByte5, headerByte4
```

字段命名的证据链是 `0x005A1900` 将窗口对象 `+0xD0/+0xD4` 分别写入 `WindowSign/WindowLevel`；`0x005C2BA0` 读取同一对象字段，传给 `0x00591E50` 的窗口标识和第二标识；后者调用 `0x0066DD60`。因此偏移8是 `WindowSign`，偏移24是 `WindowLevel`。它们由两个独立的分配表生成，不应因为现有样例相等，就永远填同一个值。

`0x005C2BA0` 还把场景窗口列表的 `end-begin` 作为映射业务函数参数11；业务函数将它传到构造函数的A字段。B来自相交屏幕计数 `local_b90/local_b8c`，C来自屏幕遍历索引。以上是已追踪创建路径的**客户端来源语义**，不是对设备固件内部变量的猜测；其它调用路径仍应选择自己的正确业务值。

## 既有预设

每节点既有序列由四类包组成：

| 操作 | 完整包 | 原函数 |
| --- | --- | --- |
| 清屏 | `FBFC61FF000000000160FDFE` | `0x0065C880` |
| 映射 | 参数化 45 字节 `61 02` | `0x0066DD60` |
| 提交 | `FBFC61B8000000000119FDFE` | `0x0065C920` |
| 刷新 | `FBFC61B900000000011AFDFE` | `0x0065C9C0` |

现有项目先清屏所有节点，再映射所有节点，再提交、刷新。原软件中这些也是独立的构造和发送入口；本轮证明了包字节来源，尚未恢复所有界面场景的完整发送时序。

两种既有预设的 400 个包与原函数逐字节一致。对任意地址、矩形及控制字段另做 40 例差分，全部一致。这证明编码规则。黄金样本的参数也来自黄金样本，不能据此证明固定A/B/C=`9/1/1`符合原界面所有布局的参数选择；例如原创建路径的C会随屏幕索引变化。

原相邻未命名入口 `0x0065B640` 构造 `FCFD5101`，`0x0065BB50` 构造 `FBFC6302`。旧版索引由于缺少未被引用的函数边界，把这些错误归入前一个函数的“型号分支”；本版已经撤销该归属。

## 跨屏计算与命令选择

`0x00591E50` 从场景的行列和每节点分辨率建立屏幕矩形，对窗口 `QRectF` 判断相交并求交集，然后转换成节点内目标矩形和源裁剪矩形。它按节点实际分辨率累计屏幕起点，不能始终假设所有节点尺寸一致。

源裁剪由窗口对象 `+0x280/+0x288/+0x290/+0x298` 的四个double值及源分辨率生成；普通裁剪和分屏输入使用不同分支。部分源宽高先按4像素对齐，并累积除法余数。源码中 `0x005EF710/0x005EF720` 的补偿钩子在本版本直接返回0。浮点伪代码的 `ROUND` 不能统一当作四舍五入：必须区分整数转换指令与后续 `QRectF::toRect`。

`0x009A3DD0` 的矩形转换原指令另做了8例验证：分别对x/y/width/height执行本版本qRound，再存成含末像素的QRect。负半像素 `-0.5→0`、`-1.5→-1`，正半像素 `0.5→1`；宽高0也保留其空矩形坐标关系。算法与[Qt 5.4的toRect实现](https://github.com/qt/qtbase/blob/v5.4.0/src/corelib/tools/qrect.h)核对，不能换用默认的银行家舍入。

第四版在隔离CPU中执行完整 `0x00591E50`，截取通用发送入口 `0x007031E0`，与独立相交／裁剪编码比较。13组全部一致，覆盖单屏、横／纵跨屏、四屏、50屏、部分相交、仅接触边界、非零源裁剪、2×2分屏输入、备用输入以及 `SendType=2/3`。原界面坐标按1/8比例表示，生成设备像素时乘8。

| 已验证条件 | 每个相交节点的发送顺序 | 输入地址 |
| --- | --- | --- |
| `SendType=1` | `6102` | `GroupIp/GroupPort` |
| `SendType=2` | `6160` | 输入单播IPv4；默认已测分类端口59993 |
| `SendType=3` | 先`6102`，再`6160`，随后处理下一节点 | 分别使用组播和单播来源 |
| 备用输入启用的已测分支 | 节点的`6102`之后发送`6202` | 独立备用来源 |

合成50屏全覆盖场景中，A为1，B/C随遍历递增到50；窗口标识7与层级3也能分别进入报文。因此固定 `9/1/1` 不能作为任意布局的参数公式。对非零源裁剪还保留了原函数的末边4像素吸附行为：比较使用裁剪尺寸，不能直接换成理想几何公式。

完整向量见 [跨屏业务验证](samples/device-layout-verification.json)。首13组使用统一1920×1080节点、无拼缝、源分片宽高为4的倍数；另 [配置分支验证](samples/layout-branch-verification.json) 补充9组独立完整包比较：

| 原配置／分类 | 已比较的选择结果 |
| --- | --- |
| `SendType=1`、IGMPv3关闭、`IsCutSynMode=0` | `6210` |
| `SendType=1`、IGMPv3关闭、`IsCutSynMode=1` | `6102` |
| `SendType=1`、IGMPv3开启 | `6120`；单播地址的第一端口为0，第二组是组播地址／端口 |
| `SendType=2`、IGMPv3开启 | `6120`；第一组为输入单播地址／分类端口，第二组为组播来源 |
| `SendType=3`、IGMPv3开启的已测输入 | 仍逐节点先`6102`再`6160` |
| 分类查询`0x005896E0`返回1／2 | 单播端口分别为59993／60000；其它已测值0走`0x005896B0`返回59993 |
| 混合节点1920×1080与1280×720 | 一个横向全覆盖场景，与独立几何及包字节一致 |

配置加载`0x00655190`确认`settings+159`来自`options/IsCutSynMode`，`+191`来自`options/IsUseIGMPSNOOPINGV3`。输入分类数字的具体设备型号仍不由样例推导。

`6120`为60字节，校验在56/57，实际仍是`sum(packet[2:40])&FFFF`。两组地址插入后A/B/C位于40/42/44，因此它们、模式46、SendType47及48～55零填充均不进入校验。不能直接把此格式按“除头尾之外全包求和”处理。

更多混合行列、拼缝及不能整除的余数分支仍缺独立比较；输入类别、节点类型及窗口属性影响的`6150/6301/6304`业务条件也没有全部关闭。基础构造采样与完整业务条件分开记录，没有实体画面验证。

## 视频矩阵、音频矩阵与 IPC

原客户端区分原生编码节点、IPC URL、平台摄像机和特殊型号。仅写入组播 IPv4 地址不能覆盖这些所有输入。

| 命令 | 格式／上下文 |
| --- | --- |
| `61 33` | 一字节选择参数；视频矩阵关闭／切换相关分支 |
| `61 0A` | 空 payload，但具有控制字节；矩阵条目与端口关闭相关调用 |
| `61 0F` | 空 payload；音频端口、矩阵端口、全窗口关闭相关调用 |
| `62 31` | 一字节模式参数；四分屏／满屏矩阵调用 |
| `61 72`、`61 73` | 两段单字节长度字符串及对应单字节选择值 |
| `61 74`、`61 75` | 一段单字节长度字符串及一个选择值 |
| `FA FA 22 00`／`22 01` | 单段字符串，零校验位置，尾 `FB FB` |
| `FA FA 23 00`／`23 01` | 同类 IPC／音频控制字符串格式 |

`61 72/73` 的 payload 可写为：

```text
lenA:u8 textA[lenA] valueA:u8 lenB:u8 textB[lenB] valueB:u8
```

`61 74/75`：

```text
lenA:u8 textA[lenA] valueA:u8
```

这些函数按 QString 的 UTF-16 单元逐个读取，再写入单字节；大于 `0xFF` 的单元写零，不是 UTF-8。长度字段按字符单元计算，且内层单段长度只有一个字节。不要直接把含中文或长 URL 的 UTF-8 字节塞进去。

字符串的业务含义由入口决定，涉及 IPC 地址、摄像机标识及输入绑定。命令格式已经恢复；每个型号下 `textA/textB/value` 的业务枚举仍需沿调用方核对。

## 音量与静音相关路径

| 命令 | 可确认含义／格式 |
| --- | --- |
| `61 90`，`0x0065FFB0` | 设置音量；一个字节的 payload，尾部校验位置写零 |
| `61 91`，`0x00660020` | 查询音量；无 payload，零校验位置 |
| `FC FD 61 91`，`0x0066C530` | 返回一个字节音量值，13 字节消息 |
| `61 C4`，`0x00660650` | 音频端口／通道控制，一字节参数；具体枚举需型号上下文 |

音量 UI 的连接路径直接证明 `61 90` 的用途。尚未根据滑杆值推断固件允许的全范围，也没有把应用自身的系统声卡音量映射成此硬件音量。

Dante 有独立 UDP 发送类和通道数据；状态 JSON 还包含输入、输出、混音、静音和延迟字段。不能把 Dante 的静音等同于 `61 90=0`。

## 背景、裁剪和镜像

| 命令 | 上下文／已恢复结构 |
| --- | --- |
| `61 80` | 背景资料查询相关；设备接收处理也会触发 |
| `61 81` | 清除背景 |
| `61 82` | 背景矩形／参数设置，16 字节 payload 的基础分支 |
| `61 83` | 背景轮询控制，两字节 payload |
| `61 C0` | 视频裁剪，8 字节矩形 payload，包含独立控制字节 |
| `61 C1` | 取消／恢复普通视频裁剪，无 payload |
| `61 A8` | 镜像方向，一字节参数；水平、垂直、组合和取消入口 |
| `61 34` | 可变长 UTF-8 文本，例如输入条目名称编辑 |
| `61 FE` | 原发送计时器使用的固定心跳／保活构造，零校验位置 |
| `61 FA` | 设备查询入口及对应返回解析路径 |

`61 34` 与上述 IPC 字符串不是同一种编码。原函数先执行 `toUtf8`，按 UTF-8 **字节数**填写长度，并计算累加校验。

更多设置、返回解析、型号分支和未命名字段统一列在 [二进制索引](catalogs/binary-commands.csv)、[构造字段差分](catalogs/constructor-fields.csv) 和 [构造样例](samples/constructor-samples.json)。每个参数改变哪些线上字节、是否连带改变长度／校验都已记录；这些采样不替代现场型号和业务参数选择。
