# SimulatorVideoJoint 通信协议逆向资料

调查版本：`TPSimulator.exe`，SHA-256 `657d4c123936901cabcf5119fb8a878a63b962f21b24a661b61a74f58f47c91d`。第四版更新日期：2026-10-09。

这组文档说明原客户端实际使用的通信协议，覆盖管理 HTTP、WebSocket、设备控制和应答、加密传输、窗口与矩阵、媒体预览、进程间通信、KVM、辅助服务、文本控制及工程传输。它是对指定版本的逆向结果，不是厂商正式规范，也不代表 SCP-cv 已接入所有能力。

**当前继续范围为涉及实际设备的客户端逻辑。** 按用户最新要求，仅软件本地、仅软件与服务端交互的逻辑停止扩展；此前已整理的 HTTP、授权、本地存储等章节保留为历史资料。服务端实现仍排除，不能把本目录称为整个软件已全部逆向完成。

## 证据等级

| 标记 | 含义 |
| --- | --- |
| 实测 | 对用户已有服务器做过请求，或者用户确认过客户端结果 |
| 原代码差分 | 在隔离 CPU 模拟器中执行原始构造／解析算法，再与独立编码或预期比较 |
| 静态确认 | 从常量、反汇编、反编译和调用链定位到格式或行为 |
| 待确认 | 仅有模板、名称、部分分支或型号关联，尚不足以定义全部语义 |

文档尽量把证据等级写在结论旁。不能把“找到一个字符串”写成“完整协议已恢复”，也不能把原客户端忽略某个字段写成设备允许任意填写。

## 范围与产物

- 主程序恢复了 444 个 Qt 类、1109 个方法的元数据；具名上下文用于识别参数和操作，不单独作为语义证明。
- 本版重新恢复完整函数边界并扩大设备成帧范围：150个构造候选完成采样，其中131个入口生成可识别报文；其余包括辅助／空返回入口。各输入参数的线上字节差分见 `constructor-fields.csv`，样例包含显式合成设置，不代表真实型号或固件范围。
- 固定解析器34类、99个输出字段完成独立解码比较；另8条扩展解析路径、30组触摸、58组Dante／标注短帧、13组标注变长包装等验证见08。
- 第四版增加完整跨屏业务13组、配置／混合尺寸9组、鼠标事件分派12组；键盘227个键的三库一致性、37个常用键独立映射和7组按键序列。CT文本106个构造入口完成采样，27组独立编码、29组列表／有效尺寸、9组图片／标题包装和16组图片分段比较通过；另恢复两套分辨率枚举74个采样。
- 设备维护新增三种EtherType `0x8066` 原始以太网构造及三种TCP命令；恢复43个Qt槽经过共用跳板后的实际入口。样例和原代码采样均来自隔离模拟器，未向设备发送。
- 额外分析了 `dllKVMTouch.dll`、`dllKVMMouse.dll`、`DLLPCToControl.dll`、`NetworkTopology.dll`、`PlayCoreGroup.exe`、`PlayCoreSignal.exe`、`PlayCoreRtmp.exe` 和 `VideoPreview.exe`。
- 标准 HTTP、WebSocket、RTSP、RTMP、H.264 和音频编解码的第三方库实现不在逐函数恢复范围；本组文档说明原软件如何调用它们，以及附加的私有格式。
- 全包EXE／DLL的指纹、导入和文件名引用候选见 `module-scope.json`。备用KVM文件名与附带SDK不自动视为当前运行模块；主要客户端模块和第三方运行库分别标注。
- 当前只继续与实际设备有关的客户端发送、接收和参数选择。固件内枚举、现场工程自定义命令和真实媒体／画面的边界保留在各章，不由软件字符串补造。

第三版更正了旧索引中的两处归属错误：相邻独立几何函数不再写成同函数的型号分支；`65F680～65FD60` 更正为Dante，标注属于 `65E3E0～65E560`。原触摸传输长度确认19字节。旧的400黄金包仍用于证明编码，映射A/B/C的业务来源另沿创建调用链核对。

第四版将标注覆盖补到 `05/06/07/08`，更正鼠标按键状态与滚轮字段，单独记录维护包内部长度与实际长度不一致、CT `<Ack>` 返回长度异常、标注16位长度回绕。新增索引为 `device-text-builders.csv`、`device-keyboard-map.csv`、`device-command-paths.csv` 和 `device-extra-builders.csv`；索引行数不等于已验证的独立协议数量。

## 使用这些资料接入 SCP-cv

先从协议和型号选择明确的入口，再按项目 Spec Kit 创建或更新规范、设计与任务。现有 `VideoWallSequenceBuilder` 的两种预设获得了原程序字节和服务器拓扑两层补充证据；任意布局、设备应答回读、加密模式及新输入类型仍是后续功能，不能只修改常量后直接宣称实体画面正确。
