# Feature Specification: 目录式现场控制台、清晰共享与摄像机音量

**Feature Branch**: `main`（沿用用户当前工作区，不创建分支）

**Created**: 2026-10-12

**Status**: In progress（软件与入口已部署，部分实体绑定待确认）

**Input**: 用户要求修复D4输入63/64的1080P裁剪、提升网页屏幕共享清晰度、将D4网页入口改为HTTP 80/HTTPS 443；媒体和预设改为从`/`开始的目录管理；加入锁定的六路摄像机流及摄像机与音量标签页；预设可选摄像机位置、音量来源/大小；首页每次切换大屏内容重发当前音量配置。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 正常拼接与清晰共享 (Priority: P1)

现场人员将D4窗口1/2映射到墙面，分享电脑桌面时能读清文字，不出现局部放大、重复或全黑。

**Why this priority**: 正确出画是现场操作的前提。

**Independent Test**: 两路1080P源的12种组合生成正确裁剪；同一文字样例对比共享前后实际接收尺寸、码率和画面；记录实体与自动化测试边界。

**Acceptance Scenarios**:

1. **Given** 输入63/64均为1920×1080，**When** 应用任意已支持的左右/全屏组合，**Then** 裁剪完整覆盖对应源，所有分片均在源边界内。
2. **Given** 用户分享1080P桌面，**When** 网络允许较高质量传输，**Then** 接收画面保留原始文字细节，不人为缩成低分辨率；网络受限时显示真实质量，不假称高清。
3. **Given** 两窗口同时共享，**When** 开始/停止/更换共享，**Then** 仍保持独占身份、关闭清理、音频和失败反馈规则。

### User Story 2 - 默认端口访问 (Priority: P1)

人员以`http://192.168.5.194`访问控制台，屏幕共享确认后进入`https://192.168.5.194`。

**Why this priority**: 不再需要记住非标准网页端口。

**Independent Test**: 在D4确认80/443可访问、HTTP不强制跳转，HTTPS证书不更换，端口冲突和现场内网防火墙范围均明确。

**Acceptance Scenarios**:

1. **Given** 用户未指定协议，**When** 打开D4地址，**Then** 默认HTTP端口80可用。
2. **Given** HTTP页面上的共享操作，**When** 用户确认切换，**Then** 跳转相同路径的HTTPS 443页面，保留必要页面上下文。
3. **Given** 80/443被非项目服务占用，**When** 部署，**Then** 明确报告冲突，不关闭无关服务或占用者。

### User Story 3 - 媒体文件管理 (Priority: P1)

媒体源以路径浏览，如`/example1.mp4`和`/examplefolder/example2.png`；类型只是筛选，不再构成导航分类。

**Why this priority**: 文件管理逻辑与用户对磁盘目录的预期保持一致。

**Independent Test**: 建目录、上传、浏览、筛选、搜索、移动、批量删除和打开到两个窗口；检查对应物理文件位置及播放中操作拒绝。

**Acceptance Scenarios**:

1. **Given** 当前目录`/examplefolder`，**When** 从媒体库上传，**Then** 新文件出现在该目录，原件保存到对应实体目录。
2. **Given** 屏幕控制页面，**When** 浏览文件夹选择源，**Then** 采用同一目录路径；从此处上传的文件默认保存到根目录。
3. **Given** 任意可播放源，**When** 点击“打开到...”，**Then** 展示小卡片，明确选择窗口1或2，一次点击发起打开并反馈真实执行状态。
4. **Given** 多选普通源，**When** 执行移动或删除，**Then** 显示明确确认及逐项结果，锁定源/播放中源不被误操作。
5. **Given** 原有媒体目录，**When** 升级，**Then** 保留原件和关联，路径变更不覆盖重名文件、不越出受管根目录。

### User Story 4 - 内置摄像机与音量操作 (Priority: P1)

内置`/Camera`目录包含五个可移动摄像机和一个固定监控。现场人员在“摄像机与音量”页面控制方向、位置预设、三类音量及音量来源。

**Why this priority**: 将现场常用摄像和声音集中到一处，避免外部软件来回切换。

**Independent Test**: 从逆向或只读设备探测核对六路地址、控制路径和音频绑定；编码/装配/权限测试加受控实体验证，不把网络写出当执行成功。

**Acceptance Scenarios**:

1. **Given** 普通用户或管理员，**When** 浏览`/Camera`，**Then** 可打开六路摄像机，但不能新增、删除、编辑、移动摄像机配置或该锁定目录。
2. **Given** 五个可移动摄像机，**When** 按住方向并松开、失焦或切换页签，**Then** 有界执行运动并停止；固定监控不显示可用转动操作。
3. **Given** 摄像机位置预设，**When** 保存或调用指定位置，**Then** 只控制选定设备，并区分写出、失败和已确认状态。
4. **Given** 大屏、手持话筒、悬挂（头戴）话筒音量，**When** 调整，**Then** 操作绑定的实际输出/通道；悬挂（头戴）对应原头戴1/2的Join1，不使用电脑总音量冒充设备音量。
5. **Given** 音量来源，**When** 选择IP81或SCP-cv，**Then** 二选一切换，软件播放输出固定绑定到对应设备，不广播到无关声卡。
6. **Given** 尚无可靠设备绑定证据，**When** 尝试实体操作，**Then** 明确禁止下发并说明缺少的配置，不猜测地址或通道。

### User Story 5 - 目录式预设与高级设置 (Priority: P2)

预设也采用目录管理，基本设置简单，高级设置可选摄像机位置与音量来源、音量大小。

**Why this priority**: 复用熟悉的目录交互，一键恢复现场方案且不误改未设置项。

**Independent Test**: 创建/移动/重命名/删除预设目录和预设；未配置高级项时激活不改设备，已配置则正确组合调用及报告失败。

**Acceptance Scenarios**:

1. **Given** 预设未设置摄像机位置，**When** 激活，**Then** 不改变任何摄像机位置。
2. **Given** 指定的部分摄像机位置与声音设置，**When** 激活，**Then** 仅调用指定摄像机，并应用明确指定的声音来源和大小。
3. **Given** 目录内预设，**When** 搜索、筛选和批量操作，**Then** 按路径管理且不丢失现有窗口、布局和音频三态规则。

### User Story 6 - 切墙后保持音量配置 (Priority: P1)

每次从首页切换大屏显示内容，完成墙面切换后重新向实际音频输出发送一次当前声音配置。

**Why this priority**: 切换图像输入不应造成音量来源或大小意外变化。

**Independent Test**: 用捕获通道证明首页墙面应用后声音配置恰好执行一次；失败不假成功，未应用/校验失败不发送声音包。

**Acceptance Scenarios**:

1. **Given** 已选择声音来源和大小，**When** 首页成功下发一次墙面布局，**Then** 紧接着重发一次当前声音配置。
2. **Given** 墙面发送失败或声音发送失败，**When** 显示结果，**Then** 区分失败阶段和可能已发生的副作用，不自动重复实体命令。

### Edge Cases

- 同名项、大小写碰撞、非法路径、路径穿越、目录循环、文件与目录同名、重解析点。
- 运行中、上传中或转换中的媒体不能被移动/删除；原件、缓存和引用同步失败不得假成功。
- `/Camera`和其内容必须在服务端保护，不能只隐藏前端按钮；批量操作需逐项识别保护对象。
- 摄像机失联、认证要求、按住方向时浏览器退出，以及预设调用中部分设备失败。
- 未选择实体音频输出、同一输出重复路由、声音切换失败、设备无可信读回。
- 同一悬挂（头戴）话筒的旧悬挂与头戴字段不同值时拒绝全部动作；相同值只写一次，旧设置与旧预设的单一字段仍可使用。
- 屏幕共享浏览器忽略建议码率、静态文本与运动内容差异、两路同时分享、源小于1080P。
- 端口/防火墙冲突、现有自签证书信任限制、数据库或文件迁移失败及部署中断。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 窗口1/2输入63/64必须默认使用1920×1080，所有裁剪必须完整覆盖源且不越界；IP81尺寸独立配置。
- **FR-002**: 屏幕共享应优先保留用户捕获源的原始尺寸、文字细节和足够传输质量，并保留原独占、安全与清理规则。
- **FR-003**: 共享质量需可诊断，区分捕获、发送、接收尺寸/帧率/码率和网络受限，不以建议参数冒充实际生效。
- **FR-004**: D4网页使用HTTP 80、HTTPS 443，默认HTTP，共享时确认切HTTPS，继续使用用户已有证书。
- **FR-005**: 媒体目录和路径从`/`开始；类型只作为筛选；支持目录浏览、全路径显示、搜索和批量操作。
- **FR-006**: 媒体库上传默认进入当前目录；屏幕控制上传默认根目录；实体保存层级与展示路径对应。
- **FR-007**: 移动、重命名与删除需保留原件、缓存关联和播放安全；非法路径、覆盖及循环需拒绝。
- **FR-008**: 媒体源提供“打开到...”小卡片及窗口1/2两个明确操作，执行结果不能仅按请求接受判为已播出。
- **FR-009**: `/Camera`内置五路可移动摄像机和一路固定监控，可播放；目录和源的相关配置不可新增、编辑、移动或删除。
- **FR-010**: 摄像机RTSP地址、转动和位置预设控制必须核对逆向资料或设备实际能力；无证据时不猜测实体协议。
- **FR-011**: 新增“摄像机与音量”标签页，覆盖方向/停止、保存与调用位置预设、三类音量和声音来源选择；悬挂（头戴）话筒统一为原头戴1/2分组Join1，两个字段别名不得重复发送或产生冲突副作用。
- **FR-012**: 声音来源为IP81/SCP-cv二选一，实际音量输出和软件声音设备必须明确绑定。
- **FR-013**: 预设采用目录式管理，高级设置支持部分摄像机预设、可选声音来源和大小；未配置项激活时保持现状。
- **FR-014**: 首页每次成功下发墙面切换后重发一次当前声音配置，失败结果区分画面与声音阶段。
- **FR-015**: 相关文档、合同、默认配置、现场验证记录同步更新；测试区分自动化、网络写出与实体确认。

### Key Entities

- **媒体目录/路径**: 父目录、名称、根路径和保护状态；源的公开路径与实体保存位置对应。
- **内置摄像机**: 稳定标识、显示名称、只读路径、播放地址、是否可移动及已确认的控制绑定。
- **现场声音配置**: 大屏/手持/悬挂（头戴）通道音量、IP81或软件来源、音频输出绑定及发送结果；头戴为悬挂的兼容别名，不是额外话筒分组。
- **预设目录/预设**: 路径、现有窗口/墙面方案、可选摄像机位置和声音设置。
- **共享质量**: 实际捕获与传输质量、网络受限原因及生命周期身份。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 两路1080P源所有12种已支持组合的裁剪越界数为0，独立输入组合实体验证有明确结果。
- **SC-002**: 在足够网络下共享1080P文字样例不人为降采样，持续两路共享5分钟不出现严重清晰度或生命周期回归。
- **SC-003**: 用户不填写端口即可从D4的HTTP/HTTPS入口访问；共享确认跳转正确，不额外开放非现场网段。
- **SC-004**: 媒体与预设可在根目录及两层子目录完成上传/创建、浏览、搜索、移动、批量删除和使用，展示/实体路径一致。
- **SC-005**: 六路内置摄像机所有修改入口均受保护；五路可移动设备的停止与位置操作有独立发送及实体验证证据。
- **SC-006**: 首页一次墙面应用后当前声音配置只重发一次；未配置高级项的预设对相应设备产生0次修改。

## Assumptions

- 沿用现有账号权限、双播放器、目录与安全规则，不引入第三播放器、PowerPoint或新的数据库服务。
- 根目录表示受管媒体根，不暴露机器绝对目录；直播源可有虚拟文件路径，不将URL当磁盘路径。
- 查询/筛选默认当前目录，搜索可覆盖子目录并展示完整路径；批量操作需确认且返回逐项结果。
- 摄像机名称和地址来自原配置/设备证据；编码输入地址不自动等于摄像机控制地址；固定监控无转动按钮。
- 2026-10-12用户更正：摄像机输入地址为8X，不是6X；五路84–88按原目录及用户规划表核对。固定监控最新更正为76，规划表“监控01”与RTSP H264/AAC元数据均吻合，不绑定89。
- 保留既有媒体和预设；新保存采用目录结构，升级先核对并保护存量，禁止覆盖原数据库或媒体。
- 实体摄像机运动和声音测试采用受控、有界操作；缺少可安全确认的绑定时先完成软件部分并准确报告限制。
