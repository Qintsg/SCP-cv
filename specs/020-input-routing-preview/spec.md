# Feature Specification: 输入路由与共享低延迟预览

**Feature Branch**: `main`
**Created**: 2026-10-21
**Status**: Implemented locally（未推送／未部署D4）
**Input**: 用户确认019方案A正式实施；移除仪表盘媒体源卡片，电视选源置于右侧电源下，大屏电源按钮内进度。新增工作站／摄像机输入、3/4预览、摄像机页预览、服务端大屏／电视记账与预案去重、Electron端直接拉RTMP/RTSP，普通Web不受影响。

**2026-10-21追加授权**：用户明确要求“推送并部署”，本轮扩展为推送GitHub／内网GitLab，D4从既有仓库快进拉取，构建独立完整运行包与网页，备份原数据后更新并启动相关服务及原桌面一键入口。仅软件部署，不额外发送墙面／电视映射、电源、云台、预案或音量控制，不更改系统分辨率／证书信任。此前本机阶段的“未部署”记录保留为历史，不再作为本轮限制。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连续、少等待的预览 (Priority: P1)

操作者打开多处同一实际流只拉／解码一份，改布局几何不全量重连；状态只用细边框。

**Why this priority**: 消除重复工作与明显首帧等待，不以降低真实稳定性换取假速度。
**Independent Test**: 多画布实际帧、同源并发、改几何／模式／一个来源的计数，以及冷／热首帧基准。
**Acceptance Scenarios**:

1. 同源65个预览共享一个传输／解码，新消费者立即取得有效最近帧；移除一处不停止其余画面。
2. 自定义比例、坐标、布局码或名称改变不重新拉未变流；真正换一个来源只影响对应订阅。
3. 真正新帧后才细绿边，短时丢帧黄边、无法连接红边；正常无流／禁用中性，不堆常驻提示，错误通过辅助状态／悬浮原因可查。
4. 冷首帧优化先关闭不必要播放器积累与缩短受控关键帧间隔，保持有界缓存／时间戳／慢消费者安全；真实基准而非HTTP200证明出画。

### User Story 2 - 统一设备目录与更多输入 (Priority: P1)

在媒体源工作站目录和方案A的其他输入中选择同一设备；窗口3/4可预览，但不启动原生播放器。

**Independent Test**: 固定目录、可达发现假传输、保护规则、四窗／别名解析和协议预检。
**Acceptance Scenarios**:

1. 工作站严格D1-1…D6-4，对应51–74共24，75不存在；76监控01、81现场，84后／85中1／86中2／87左／88右。
2. 工作站内置目录列出当前服务可达设备；发现有缓存、并发及超时上限，不持续拉全部媒体，也不把TCP可达伪报出画。
3. 窗口1–4来源63–66；3/4只有预览／输入路由，原生播放窗口数仍为2。
4. 其他输入二级菜单可搜索／滚动，标签只显示IP末段；来源／组播与服务器目录统一，不让前端任意指定控制帧。

### User Story 3 - 大屏与两电视单路选源 (Priority: P1)

仪表盘采用A，右侧电源下方有电视左／右选源；两电视各只显示一个输入，电源控制仍独立。

**Independent Test**: 原逆向矩阵构造的独立黄金帧、假设备发送顺序、REST／页面事件。
**Acceptance Scenarios**:

1. 电视用独立矩阵协议，不套用50屏clear/map/commit/refresh；未知／不可验证的参数首包前拒绝。
2. 单台电视和大屏可手动重发同样内容，不强行按去重结果禁用仪表盘。
3. 电源按钮对齐、危险关机仍确认；大屏按钮内显示进行中的发送进度，不虚构开机百分比或实体已开状态。
4. 仪表盘不放媒体源目录卡片；媒体源页仍保留完整目录工作流。

### User Story 4 - 预案只改必要输出 (Priority: P1)

预案分别配置大屏、电视左／右，服务端保存上次完整成功下发内容，未变时跳过重复切换。

**Independent Test**: 持久化、失败／未知／重启、并发与预案YAML round-trip及发包计数。
**Acceptance Scenarios**:

1. 每个输出有独立记录，保持不派发，相同来源／几何且记录可信时预案跳过；仪表盘强制发送不跳过。
2. 来源IP相同但几何／裁切变化仍执行必要配置，不能把它当作完全未变。
3. 发送前标记进行中；部分失败／取消／记录不确定后不能沿旧记录跳过。只在完整写出后保存成功记录，不伪装硬件实时读回。
4. 预案窗口内容改变但输出仍指同一输入时，不重复切换墙／电视；其它音量／摄像机／媒体动作仍遵原合同，不因输出跳过而整案跳过。
5. 旧预案未配置电视时保持；YAML、索引与编辑器一致，不静默丢失新字段。

### User Story 5 - Electron本机直拉，不改Web路径 (Priority: P1)

Electron使用随包提供的媒体组件在用户设备直接取RTMP/RTSP，尽量保留源画质并减少中转。网页继续使用服务端按需FLV。

**Independent Test**: 实际Electron44.2 app协议流、合成RTMP/RTSP、客户端自有进程／异常退出及Web回归。
**Acceptance Scenarios**:

1. 用户无需另外安装Node、FFmpeg或.NET；渲染进程不能获得任意进程启动／URL代理能力，保持沙箱、隔离、CSP与正常TLS。
2. H264优先原码转封装，无预览音轨；不兼容时受控退回兼容编码，不同时启动第二份同源拉流，不声称任意格式无损。
3. 源地址／凭据仅进入受限主进程与私有运行进程，不进渲染UI、流URL或日志；绑定已提交主机、完整登录寿命、来源修订和可信顶层调用者。
4. 换主机、登出、迟到返回、离屏／离页／关闭／源变更及时回收；强杀Electron或helper、上游停数据时仍有界清理，无无主FFmpeg。
5. Web不调用原生IPC、不要求工具、不改为客户端直拉；Electron能力不可用须明确，不静默宣称已走直连。

### User Story 6 - 对照CameraBOX完善摄像机体验 (Priority: P2)

摄像机页展示所选设备预览与控制；只使用已证实控制码，保留停止和位置覆盖确认。

**Independent Test**: 九字节原样本、固定监控禁控、切摄像机停止围栏和当前预览订阅。
**Acceptance Scenarios**: 方向／变焦31–36与附件一致；不把39／45误当两个独立预置位，不引入Python运行时，不把未校验11字节接收当设备确认；只有当前选择预览，监控76可看不可转动。

### Edge Cases

- 不同密码、路径、协议、chn0/chn1不得仅凭IP错误合并；几何不自动触发通道重选。
- 完整登录票据轮换、同账号重登、主机ABA、旧租约迟到清理，不污染新归属。
- 输入离线、原始GOP慢、H265等兼容问题、服务／helper崩溃、部分控制写出、状态提交失败。
- 原控制软件或物理重启可能改变画面，记录只是上次下发；未知时重发，允许人工同源重发恢复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 实施A二级选源及仪表盘右侧电源／电视布局，移除原型媒体目录卡片，去掉多余提示。
- **FR-002**: MUST 浏览器同实际流共享传输与解码，几何变更不重连，引用回收有界且认证切换立即失效。
- **FR-003**: MUST 实测降低冷首帧等待，保留完整GOP／慢消费者／码率预算与错误恢复；预览1px三态，不拿受理当帧。
- **FR-004**: MUST 提供受保护工作站目录和有界可达发现；源表严格按用户更正，窗口3/4仅输入／预览。
- **FR-005**: MUST 统一工作站／摄像机／窗口别名及受限组播输入，不放开任意设备控制或未知几何。
- **FR-006**: MUST 电视采用独立已恢复矩阵协议，左右各一路，支持与大屏相同的已许可输入；电源仍独立。
- **FR-007**: MUST 服务端持久记录各输出上次完整成功下发，区分进行中／失败／未知，不标为物理读回。
- **FR-008**: MUST 预案保持及未变跳过按输出生效，几何变化仍下发，仪表盘明确强制重发；旧预案默认电视保持。
- **FR-009**: MUST 预案编辑／YAML／索引／合同同步新输出字段，保留原摄像机、音量、媒体及失败语义。
- **FR-010**: MUST 大屏电源按钮内显示发送进行状态与完成，不虚构硬件进度；危险动作确认／归属／防重保持。
- **FR-011**: MUST Electron受限主进程直拉RTMP/RTSP，所需运行时随包，H264优先原码转封装，Web不受原生路径影响。
- **FR-012**: MUST 原生预览具备可信调用者、票据／主机／源寿命、防原始凭据泄露、独占进程及异常退出回收。
- **FR-013**: MUST CameraBOX核对及摄像机当前预览接线，不移除现有安全停止与机位保护。
- **FR-014**: MUST 更新OpenAPI3.0并用Redocly校验，文档／声明／规范／分层测试同步；未证实体与发行许可边界明确。

## Success Criteria *(mandatory)*

- **SC-001**: 65同源画面只1传输／1解码；同源新增可消费最近真实帧，纯几何变更连接增量0，换一处不重连其它流。
- **SC-002**: 相同受控合成源冷首帧p50／p95较018基线下降，至少5轮记录实际帧回调；不得用预览创建或首字节代替。
- **SC-003**: 默认测试现场发送／真实设备连接0；静态黄金帧与独立回环覆盖电视协议，未做实体出画时明确。
- **SC-004**: 连续相同预案两次，第二次每个未变输出包数0；手动同源重发仍有包；失败／未知／几何变更不错误跳过。
- **SC-005**: Electron受控源验证原码尺寸／帧，普通Web没有新IPC调用；强杀父或helper后自有媒体进程≤5秒全部退出。
- **SC-006**: 桌面／手机无横向溢出，预览边框1px；按钮／菜单／预案各状态通过真实渲染与组件回归。

## Assumptions

- 用户已批准A正式实现；当前只提交本机保存点，不推送／部署D4，除非后续另获请求。
- H264原码转封装不能解决源编码本身的延迟；其它编码可能转码，不能承诺所有场景无损／永不断流。
- 包内媒体运行时须附匹配许可证／来源／构建清单；公开分发前必须满足对应源码义务，非商业不代表自动豁免。
- 设备无可信实时读回时使用上次下发的逻辑记录；失败或已知失效时不得用于跳过。
