# Feature Specification: 大屏专用控制与媒体整理

**Feature Branch**: `main`（本仓库未配置 Spec Kit 建分支 hook）

**Created**: 2026-09-27

**Status**: Draft

**Input**: User description: "停止测试并关闭服务；只保留大屏播放窗口 1、2，但保留两台电视电源；大屏支持手动输入与区域映射及原单/双屏预设；PPT 默认上传转图片、实验性启用 PowerPoint；媒体文件按页面文件夹存储并可转移。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 控制两块大屏 (Priority: P1)

现场操作员打开控制台后，只看到大屏的播放窗口 1、2。播放器在 D4 只占用两块大屏输出；用户可为大屏左、大屏右或全屏手动选择窗口 1、窗口 2、现场笔记本输入或自定义 IP 流，也可一键使用“窗口 1 全屏”和“窗口 1 左／窗口 2 右”两个预设。

**Why this priority**: 删除小电视时不能中断大屏的实际用途。

**Independent Test**: 仅用窗口 1、2 完成源选择与播放；两个固定预设维持原有墙面行为；手动配置可保存、预览、验证冲突。未抓获控制帧的映射明确显示“暂不可下发”，不报告成功。

**Acceptance Scenarios**:

1. **Given** 两个大屏输出可用，**When** 分别给窗口 1、2 选择不同媒体源并用双窗预设，**Then** 左右输出对应窗口内容，互不串台。
2. **Given** 双窗预设，**When** 切换为窗口 1 全屏再恢复，**Then** 墙面分别按现有两个预设的行为映射；窗口 2 的不可见与静音行为保持一致。
3. **Given** 用户建立一项含现场笔记本或自定义 IP 流的手动映射，**When** 对应帧协议尚未完成抓包验收，**Then** 可保存和预览意图，但实体下发被明确拒绝且当前墙面保持不变。
4. **Given** 任一控制端，**When** 查看导航、仪表盘、显控、预案和设置，**Then** 可操作播放窗口仅为 1、2。

---

### User Story 2 - 退役小电视播放能力 (Priority: P1)

操作员不再看到两个小电视的播放窗口或显示器选择。系统不再启动小电视专属播放器，旧窗口编号不再接受新播放命令；两台电视原有的电源切换入口继续保留，与大屏播放目标区分显示。

**Why this priority**: 已停用的入口会造成误操作及不可见的硬件副作用。

**Independent Test**: 播放页面只含大屏窗口；设备电源仍有拼接屏和两台电视；旧窗口调用得到明确拒绝，不生成播放命令或启动播放器。

**Acceptance Scenarios**:

1. **Given** 系统启动，**When** 查看运行状态，**Then** 只有两个受管播放器与两个播放会话，且仅占用两块大屏输出。
2. **Given** 旧客户端请求控制窗口 3 或 4，**When** 系统接收请求，**Then** 返回无效窗口错误，且大屏状态不变。
3. **Given** 操作员查看电源控制，**When** 打开页面，**Then** 仍可看到拼接屏明确开/关及两台电视各自的切换命令，并能辨认电视无状态读回。

---

### User Story 3 - 安全处理旧配置 (Priority: P1)

已有媒体和配置不因退役小电视而被删除；旧预案若仍要求操作窗口 3、4，明确拒绝激活，避免“成功”但只执行一半。

**Why this priority**: 静默忽略旧预案目标会造成错误的成功反馈。

**Independent Test**: 含 3、4 有效目标的旧预案在副作用前拒绝；移除旧目标后只操作窗口 1、2；媒体文件仍在。

**Acceptance Scenarios**:

1. **Given** 旧预案的窗口 3 或 4 目标不是“未设置”，**When** 激活，**Then** 在任何播放或硬件副作用之前拒绝，并指出旧目标。
2. **Given** 旧预案的窗口 3、4 均为“未设置”，**When** 激活，**Then** 只按窗口 1、2 与大屏模式执行。
3. **Given** 升级前已有媒体和数据库记录，**When** 部署新版本，**Then** 不因本功能自动删除这些数据。

---

### User Story 4 - PPT 默认逐页图片播放 (Priority: P1)

操作员上传 `.ppt` 或 `.pptx` 时保留原始文稿，同时生成按页排序的图片。上传转换阶段可使用 PowerPoint；播放默认只使用这些图片进行翻页，不调用 PowerPoint 放映。如现场确需原生放映，管理员须先在设置中显式开启标有“实验性”的 PowerPoint 模式。

**Why this priority**: 默认播放不应受 Office 自动化实例和放映窗口争用影响。

**Independent Test**: 上传多页文稿后能核对原件与逐页图片；不开实验开关可播放、翻页，且播放过程不新建 Office 放映实例；打开实验开关后才允许原生放映。

**Acceptance Scenarios**:

1. **Given** 新上传有效多页文稿，**When** 上传完成，**Then** 原文件与每页图片都可用，默认打开显示第一页，翻页顺序正确。
2. **Given** 实验开关关闭且上传转换已完成，**When** 播放 PPT 源，**Then** 不启动 PowerPoint 放映实例。
3. **Given** 管理员明确启用实验性模式，**When** 选择 PPT 原生放映，**Then** 界面提示风险并可使用保留的原文件；失败时如实报告。

---

### User Story 5 - 媒体按用户文件夹存储与转移 (Priority: P1)

操作员在页面上创建“PPT文件”等文件夹或子文件夹，上传到该文件夹的文件实际位于对应媒体目录；根目录上传则直接位于媒体根目录。将源移入或移出文件夹、重命名或移动文件夹时，原件物理路径同步转移；按源 ID/摘要独立保存的逐页图片关联持续有效。

**Why this priority**: 用户需要文件系统路径与页面组织一致，便于现场查找、备份和维护。

**Independent Test**: 根目录上传 `a.pptx` 的原件位于 `media/a.pptx`；上传到“PPT文件”的 `b.pptx` 位于 `media/PPT文件/b.pptx`；移动后路径和下载、预览、播放均更新且内容哈希不变。

**Acceptance Scenarios**:

1. **Given** 用户在指定文件夹上传媒体，**When** 上传完成，**Then** 原件位于对应文件夹下，页面与下载都指向同一内容。
2. **Given** 用户移动媒体到另一文件夹，**When** 操作成功，**Then** 原件及衍生文件一起移动，旧路径不再作为当前路径，播放和下载仍可用。
3. **Given** 文件名冲突、非法 Windows 路径名或磁盘错误，**When** 上传或移动，**Then** 不覆盖现有文件，不把数据库与文件留成不一致的“成功”状态。
4. **Given** 用户移动或重命名文件夹，**When** 操作成功，**Then** 其内所有受管理媒体的真实路径随目录层级更新，预览、下载与播放仍可用。

### Edge Cases

- 旧窗口 3、4 地址不能显示可操作的显控页，也不能绕过后端拒绝。
- 运行组重启、健康状态、窗口编号提示和异常清理只依赖两个播放器。
- 旧预案同时含大屏模式和退役窗口目标时，应先拒绝，不能先改变物理墙面。
- 全屏映射与左右分区映射互斥；每个分区最多一个输入；自定义 IP 流无效时不能下发未知帧。
- PPT 转换失败、页数为零或原件损坏时，不能把不可播放的图片模式标记为上传成功。
- 文件夹重命名、删除、移动和同名文件冲突必须处理物理路径；不允许把文件夹移入自身或子孙目录。旧日期目录文件保留到明确迁移或用户移动时，不自动删除。
- 本功能的本地验证不自动重新开启已关闭的 D4 服务、电源或墙面。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 所有控制端 MUST 只展示大屏窗口 1、2 的导航、状态和播放操作，并移除小电视专属播放控件；两台电视的电源控制 MUST 保留。
- **FR-002**: 运行组 MUST 只创建和管理两个播放器，且它们只占用 D4 的两块大屏输出、不得选择小电视或控制桌面；启动、就绪、停机、重启与故障报告不得依赖窗口 3、4。
- **FR-003**: 系统 MUST 只维护窗口 1、2 的有效播放会话；所有接受窗口编号的入口 MUST 拒绝 3、4 及其他非法编号，不入队、不产生物理副作用。
- **FR-004**: 大屏 MUST 提供左、右、全屏目标的手动输入映射，输入可选窗口 1、窗口 2、现场笔记本或自定义 IP 流；全屏与左右互斥，不允许同一分区多个输入。
- **FR-005**: 大屏 MUST 提供固定的“窗口 1 全屏”和“窗口 1 左／窗口 2 右”两个预设，并保持现有已验证控制帧与静音行为；新映射控制帧在现场抓包确认前 MUST 明确拒绝实体下发，不得假报成功。
- **FR-006**: 拼接屏明确开/关与两台电视的原有电源切换 MUST 保留；电视状态无法读回的事实 MUST 在界面及文档中说明。
- **FR-007**: 新建、编辑、预览、捕获与激活预案 MUST 只面向窗口 1、2；既有预案若包含 3、4 的有效目标，激活 MUST 在任何副作用之前给出明确拒绝，不得假报成功。
- **FR-008**: PPT/PPTX 上传 MUST 保留原件并生成有序逐页图片，转换阶段 MAY 使用 PowerPoint；默认播放 MUST 只使用图片而不调用 PowerPoint 放映；原生 PowerPoint 放映 MUST 由跨控制端一致的设置中显式实验性开关控制，默认关闭且仅影响后续打开。
- **FR-009**: 页面文件夹及子文件夹 MUST 对应媒体目录中的真实层级；新上传的原件 MUST 按当前文件夹保存而不是按日期保存。用户移动源或移动/重命名文件夹时，原件物理路径 MUST 同步更新，独立缓存的衍生页图关联 MUST 保持可用。
- **FR-010**: 文件夹及文件名 MUST 经过 Windows 路径安全校验；冲突时 MUST 生成明确且不覆盖的目标名称或拒绝；失败时 MUST 不遗留数据库与文件路径不一致的成功状态。
- **FR-011**: 旧日期目录中的原件 MUST 保留；升级不自动删除媒体、数据库或日志，旧源可经用户操作迁入新目录结构。
- **FR-012**: 媒体库、背景音乐和系统音量等无关能力 MUST 保留；用户说明、运维指引、接口说明和自动验证 MUST 与新行为一致，历史四窗测试记录可保留并标明旧版本证据。

### Key Entities

- **大屏播放窗口**：编号 1 或 2，具有播放会话、媒体源、显示输出及控制状态。
- **大屏模式**：单屏或双屏，决定可见性、映射和静音策略。
- **大屏映射**：输入来源与左、右或全屏目标的组合；两个已验证预设可实体下发，其余组合等待协议抓包。
- **预案目标**：针对一个有效窗口的“未设置／清空／指定源”操作；历史目标可存在但不得对退役窗口执行。
- **设备电源**：拼接屏支持明确开关，两台电视仅支持切换、无状态读回。
- **媒体文件夹**：由用户命名、可嵌套的文件夹，对应媒体根目录下的实体目录。
- **PPT 衍生页**：由保留的文稿原件转换出的有序图片集合，作为默认播放内容。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 桌面、手机和封装控制端的全部播放入口中，窗口 3、4 的操作项出现次数为 0；两台电视电源操作项仍可找到。
- **SC-002**: 每次成功启动的大屏运行组恰有 2 个播放器，停止后这 2 个播放器均退出；不启动或等待第 3、4 个播放器。
- **SC-003**: 对旧窗口 3、4 的控制请求，100% 在执行前被拒绝，且大屏与硬件状态不变。
- **SC-004**: 大屏窗口 1、2 的源打开、关闭、两个已验证预设及仅含有效目标的预案，在本地自动化与浏览器验证中全部通过；未抓包的映射 100% 被阻止下发。
- **SC-005**: 含有效旧小电视目标的预案，100% 在任何副作用前被拒绝；升级前的媒体文件及数据库记录不因本功能被删除。
- **SC-006**: 有效多页 PPT/PPTX 上传后，原件和全部页图可检索，默认翻页顺序正确；实验开关关闭时默认播放产生的 PowerPoint 放映实例数为 0。
- **SC-007**: 新上传及经页面移动的媒体，100% 位于页面所示文件夹对应的媒体目录，下载内容哈希不变；重名和非法路径测试 100% 不覆盖已有文件。

## Assumptions

- “只做大屏”只退役小电视播放窗口 3、4；用户随后明确要求保留两台电视电源控制。
- 窗口 1、2 分别对应现有大屏左右输出；用户已确认“占用两个显示器”仅指两块播放输出，控制桌面照旧。
- 新手动映射的实体帧协议由后续现场抓包提供；当前可先保存、预览、校验意图，但不能猜测并下发控制帧。
- 允许上传转换阶段使用 PowerPoint，但默认播放不使用 Office 放映；旧日期路径不批量迁移，避免在服务关闭期间动用户数据。
- 不默认引入 MongoDB；现有单写入者数据库足以存放媒体元数据，文件移动的一致性仍需文件系统流程保证。
- 用户要求停止现场测试，本任务不重启 D4 服务或做实体复测；允许本机不触碰硬件的自动化验证。
- 历史测试文档作为审计记录保留，当前操作文档和合同改为两窗口语义。
