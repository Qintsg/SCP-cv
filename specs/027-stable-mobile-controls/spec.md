# Feature Specification: 稳定播放控制与手机工作台

**Feature Branch**: `main`
**Created**: 2026-10-27
**Status**: Implemented
**Input**: 修复滑块与状态更新引起的页面跳动，简化PPT控制，改善共享清晰度，并适配手机悬浮玻璃底栏及精简界面。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连续调整且页面稳定 (Priority: P1)

操作人员拖动音量或定位滑块时，控件跟随手指，页面内容保持位置，最终值完成提交。

**Why this priority**: 位置跳动会中断触摸操作。
**Independent Test**: 连续输入和跨事件收尾，检查提交次数、最终值、状态区域的位置及换源后的行为。

**Acceptance Scenarios**:

1. **Given** 正在拖动滑块，**When** 收到请求和状态更新，**Then** 当前滑块位置及页面几何保持稳定。
2. **Given** 最终值已经提交，**When** 同次拖动结束，**Then** 合并重复收尾；新的独立操作仍可提交同值。

### User Story 2 - 简洁演示控制 (Priority: P1)

演示文稿主控制区使用“上一步”“下一步”两个按钮；动态文稿按动画步操作，静态文稿使用对应翻页。

**Why this priority**: 集中主要动作，减少现场误操作。
**Independent Test**: 核对按钮、键盘动作、静态文稿和末页无操作反馈。

**Acceptance Scenarios**:

1. **Given** 动态文稿，**When** 按钮或方向键推进，**Then** 执行对应动画步。
2. **Given** 静态文稿，**When** 使用相同导航，**Then** 执行翻页。

### User Story 3 - 手机触摸工作台 (Priority: P1)

手机竖屏使用悬浮玻璃底栏，主要操作触控方便；手机界面优先显示控制信息，移除非必要预览。

**Why this priority**: 减少手机资源消耗和操作距离。
**Independent Test**: 手机竖横屏、深浅色、安全区及预览请求检查。

**Acceptance Scenarios**:

1. **Given** 手机竖屏，**When** 浏览内容，**Then** 底栏悬浮且末尾内容可完整滚动显示。
2. **Given** 手机控制端，**When** 打开媒体、墙面和摄像机页面，**Then** 保留操作与墙面几何，停止非必要预览加载。

### User Story 4 - 清晰屏幕共享 (Priority: P2)

屏幕共享使用更高且前后一致的可配置视频码率，页面突出共享与停止操作。

**Why this priority**: 改善现场文字和细节表现。
**Independent Test**: 核对服务策略、真实编码参数与接收帧，调整捕获尺寸后核对发送上限。

**Acceptance Scenarios**:

1. **Given** 不同分辨率的共享，**When** 协商视频，**Then** 使用主机发布的上限并保留网络拥塞控制。
2. **Given** 共享尺寸发生改变，**When** 进入新的像素档位，**Then** 更新发送策略并显示实际配置。

### User Story 5 - Pad横竖屏控制台 (Priority: P1)

Pad用户在横屏和竖屏均使用悬浮玻璃底栏，查看媒体和摄像机预览，并使用完整的文稿预览及控制。

**Independent Test**: 检查600×960、800×1280及其横屏尺寸，确认预览、导航、安全区与旋转后的组件保持，并生成签名APK。

**Acceptance Scenarios**:

1. **Given** Pad横屏或竖屏，**When** 打开主要页面，**Then** 使用悬浮玻璃底栏，保留已有预览入口与内容。
2. **Given** 已打开Pad预览，**When** 横竖屏旋转，**Then** 根据空间调整布局，保留相同来源的预览组件。
3. **Given** 手机或桌面，**When** 打开相同应用，**Then** 保持对应设备的预览和导航规则。

### Edge Cases

- 换源、换主机、退出和资源释放保留既有合同。
- 真实失败提供固定位置的反馈；状态更新不频繁插入整块布局。
- 手机移除预览同时释放订阅，转动设备不恢复不必要拉流。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 合并同一次滑块拖动的重复提交并保留最终值、独立操作及作用域失效行为。
- **FR-002**: MUST 将频繁更新的状态和反馈置于稳定区域，保持主要操作位置。
- **FR-003**: MUST 使用统一的两个文稿导航按钮，键盘与按钮使用相同动作。
- **FR-004**: MUST 参考成熟演示控制设计组织预览、页码、备注与主要操作。
- **FR-005**: MUST 为手机提供悬浮玻璃底栏、安全区及触控尺寸，保证内容不受遮挡。
- **FR-006**: MUST 在手机移除非必要实时预览和缩略图，并停止相应加载与订阅。
- **FR-007**: MUST 由播放主机发布可配置的共享视频策略，提高默认码率；动态尺寸更新与实际配置一致。
- **FR-008**: MUST 精简共享及相关控制中的重复说明，并验证真实代码、服务和页面。
- **FR-009**: MUST 推送两个仓库、部署D4，并提供本机桌面的Windows x64便携ZIP与签名Android arm64-v8a APK；制品对应当前提交，保持既有媒体和硬件绑定。
- **FR-010**: MUST 为Pad横竖屏提供悬浮玻璃底栏与安全留白，保留预览和触控操作，并提供桌面的签名arm64-v8a APK。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同次拖动结束不产生相同最终值的额外提交，最终值正确。
- **SC-002**: 连续状态更新时，主要控制区的纵向位置保持不变。
- **SC-003**: 文稿主导航始终为两个按钮，动态与静态操作分别正确。
- **SC-004**: 手机页面非必要预览订阅和图像、视频加载为零，底栏不遮挡末尾内容。
- **SC-005**: 不同分辨率下，真实发送参数与主机策略一致，共享接收端持续获得有效帧。
- **SC-006**: Pad四种目标尺寸均显示悬浮底栏、保留预览、无页面横向溢出，最后操作区可以滚动至底栏上方；旋转不重新挂载相同预览。

## Assumptions

- 现有Vue、Ant Design、Electron和Capacitor客户端继续共享代码。
- 2026-10-27用户授权推送、部署及客户端打包；部署不改变Windows显示模式或现场设备设置。
- 保留现有桌面预览、设备控制、媒体和共享授权语义。
