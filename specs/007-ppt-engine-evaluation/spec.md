# Feature Specification: 免费文稿引擎本机可靠性评估

**Feature Branch**: 沿用当前工作区，不切换或提交暂停中的改动

**Created**: 2026-09-29

**Status**: Evaluation

**Input**: 用户要求本机测试 WebView2 + pptx-viewer 和 LibreOffice Impress + UNO 的实现效果，以及稳定使用、避免严重 bug 的难度；不得购买商业许可。

## User Scenarios & Testing

### User Story 1 - 比较真实文稿效果 (Priority: P1)

用户需要了解同一批文稿在两种候选方案中的排版、中文、动画和多媒体实际表现，不能只凭打开成功选择引擎。

**Why this priority**: 内容保真是候选方案是否可用的前提。

**Independent Test**: 对资源目录中的两份文稿记录摘要、页数、功能覆盖以及逐项实际结果。

**Acceptance Scenarios**:

1. **Given** 原文稿和已知页图参考，**When** 在候选方案中显示各页，**Then** 记录文字、图形、字体或媒体缺失，不能用页数正确代替视觉验收。
2. **Given** 包含点击动画和媒体的文稿，**When** 逐步推进、跳页和暂停，**Then** 区分真实播放、近似效果、明确不支持和失败；记录媒体时间推进不等于听觉验证。

### User Story 2 - 判断稳定使用难度 (Priority: P1)

用户需要知道两种方案从短时能运行到稳定使用仍需解决的严重缺陷和工程边界。

**Why this priority**: 崩溃、卡住、关闭残留与错误控制比原型代码行数更影响现场可靠性。

**Independent Test**: 有界重复导航、重新加载、关闭和双实例隔离，保留原始错误与资源样本。

**Acceptance Scenarios**:

1. **Given** 健康文稿，**When** 至少尝试 10 次打开/关闭和 100 次导航，**Then** 记录实际完成次数、超时、错误、资源趋势及残留；若提前故障，不能换小样本宣称原门禁通过。
2. **Given** 错误或缺失输入，**When** 尝试打开，**Then** 不假报成功，并记录后续健康文稿是否可恢复。
3. **Given** 两个独立播放目标，**When** 只控制其中之一，**Then** 核对另一个目标不被改变；未完成承载测试的路线明确标为未验证。
4. **Given** 两窗同源或异源并存，**When** 一窗反复替换两份文稿、关闭再重开，**Then** 核对另一窗实际页码/媒体不受影响，同时记录关闭耗时、旧媒体停止、文件锁和进程残留。

### User Story 3 - 隔离实验和正式服务 (Priority: P1)

本机实验不应恢复 D4 服务、改变正式默认播放方式或损坏用户文稿。

**Independent Test**: 实验前后工作区与原件摘要一致，仅新增本轮报告、规范及忽略的实验产物。

**Acceptance Scenarios**:

1. **Given** D4 任务暂停及本机已有改动，**When** 运行实验，**Then** 不访问 D4、不修改生产文件或旧任务内容。
2. **Given** 本轮登记的独立进程与文件，**When** 收尾，**Then** 仅清理自有运行进程；用户应用、原件和既有证据保留。

### Edge Cases

- 大文稿、缺失字体、旧音视频编码、长时间加载、原文件不存在或损坏。
- 动画推进与直接换页混淆；媒体元素存在但时间不推进；关闭后仍有声音或进程。
- 图像预览能显示但动画引擎不支持；普通浏览器成功但实际宿主失败。
- 外部放映成功但不能稳定承载到应用窗口；原生绑定版本或进程隔离不兼容。

## Requirements

### Functional Requirements

- **FR-001**: MUST 使用同一批原件的只读副本，记录 SHA-256、页数和内容覆盖，不向公共服务上传文稿。
- **FR-002**: MUST 分别验证排版、动画和音视频；不支持项及测试覆盖缺口必须列出。
- **FR-003**: MUST 比较实际应用窗口承载与普通预览的差异，不能以外部窗口或图片输出冒充内嵌动态播放。
- **FR-004**: MUST 有界测试反复控制和生命周期，记录严重故障、恢复方法、资源趋势和精确进程归属。
- **FR-005**: MUST 区分已观察事实、推断、官方声明和未验证项；测试失败也是选型结果，不修改供应方库来隐藏失败。
- **FR-006**: MUST 不购买许可、不接入生产、不恢复 D4；原实验和暂停中的改动保持可恢复。
- **FR-007**: MUST 重点验证多开、两文稿交叉切换和关闭；单窗重复成功不得冒充两窗隔离稳定性。

### Key Entities

- **测试文稿**：摘要、大小、页数、动画/媒体覆盖、参考图及原件路径。
- **实验运行**：候选版本、宿主身份、动作、时间、状态、错误、资源和退出证据。
- **评估结论**：保真缺口、严重风险、缓解工作和当前验证边界。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 两种候选均给出同文稿的实测结果或具体不能运行的原因，不能只给纸面推荐。
- **SC-002**: 每条路线的反复操作均有实际计数、完成/失败及原始证据，并明确短时测试不能证明长期无 bug。
- **SC-003**: 最终报告按内容兼容、控制正确性、承载、隔离、恢复、资源及部署复杂度比较稳定使用难度。
- **SC-004**: 原件摘要不变，D4 不操作，实验服务收尾且既有改动保留。

## Assumptions

- 仅本机 Windows 测试，不构建完整生产接入，也不开展 D4 长稳或设备电源测试。
- 不做系统音量写入；媒体默认静音，播放时间证明解码推进，不证明音箱输出正确。
- 本轮支持动态内容的测试文稿不足以覆盖所有 PPT 功能；缺过渡等内容时明确记录缺口。
- 有界实验不能证明未来无严重 bug，难度结论依据已复现缺口和必要的稳定化工作。
