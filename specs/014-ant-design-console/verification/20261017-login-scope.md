# T022 登录意图与完成归属

日期：2026-10-17。仅本机真实Ant/Auth/API、路由与生产SPA；账号/密码和认证响应均为虚构内存数据，不登录现场或修改真实用户。

## 原始失败

有效初轮39项中3绿36红。实际生产旧构建还重现两条：登录密码请求401迟到将已进入的连接页拉回登录；CSRF200在离页后仍继续发送密码，原目的地也随当前route.query改变而漂移。对应原始日志和逐请求记录保留，不以源码推断替代实测。

同轮双提交样例在原Ant下也有通过结果，作为正对照，不能宣称它已在真实浏览器稳定复现两次提交；本轮仍按任务补显式同步锁，避免依赖组件验证调度。初版测试脚本括号语法错误不计入产品红回归。

## 实现

- LoginView冻结用户名/密码/redirect、页面完整路由、本地意图、真实/投影代次与主机地址。同步防重，成功/取消/离页/换主机清旧界面密码；当前失败仍允许修改后显式重试。旧finally不解锁或清空新提交，卸载释放主机订阅。
- Auth.login复用`AuthenticationOperationOptions.canContinue/onCommitted`，在CSRF后、发送密码前、提交身份前复核；完成后重新捕获认证凭据。保留原AuthUser返回值，不将自身成功误判过期；回调与检查器引用在入口冻结。
- HTTP层在派发、正文解析/401回调前复核调用归属，CSRF缓存赋值也复核，不能只在组件catch中隐藏旧提示。探测的CSRF/status同步接入，原生失活后的旧401也不再先触发全局导航。
- `requestJson`第四参数为命名的本地归属选项，不进入HTTP。清会话例外仍只限切换期间固定POST logout，不扩展业务权限；普通当前401和原错误说明、既有当前CSRF读取失败后单次登录回退策略保持，不自动重放密码。
- 当前错误与原生输入用`aria-describedby`关联；路由离开/更新守卫及主机变化使旧意图失效。清输入不等于撤销已发送HTTP、清Cookie或擦除JS字符串内存。

## 验收断言纠正

首批浏览器8例曾报告通过，但截图与结果仍出现登录页。根因是正则`/sources$`也匹配`/login?redirect=/sources`，并不能证明进入媒体页；不是已确认的正常产品路由回跳。

这批初判不作最终验收。改用精确完整URL、媒体页真实操作按钮、截图后再次复核路径；移除临时history方法包装后，重新跑完8例通过。没有为测试误判修改正常路由策略。浏览器首轮双提交“通过”也不作为最终页面稳定的证明。
