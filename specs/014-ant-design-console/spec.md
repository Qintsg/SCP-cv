# Feature Specification: Ant Design 现场控制台重构

**Feature Branch**: `main`（沿用当前工作分支）

**Created**: 2026-10-16

**Status**: Implemented（本机验收完成，未部署）

**Input**: 仪表盘布局选好后直接应用，不再先保存草稿；删除发送状态、发送详情及上次发送布局。使用 Ant Design 重构前端，并参考同类开源项目重新优化布局，不照搬现有排布。

## User Scenarios & Testing

### User Story 1 - 一次应用大屏布局 (Priority: P1)

现场人员选择单屏或双屏，分别选择窗口1、窗口2、IP81或已登记的输入，再点击一次“应用布局”。不必理解草稿、修订号或发送日志。

**Why this priority**: 高频操作需要减少步骤，且不能错发上一次的布局。

**Independent Test**: 修改任意区域的输入，点击一次应用；观察请求只针对本次选择，不先要求手动保存。

**Acceptance Scenarios**:

1. **Given** 已进入仪表盘，**When** 选择窗口2全屏并点击应用，**Then** 当前选择被提交一次，不显示保存草稿按钮或未保存徽标。
2. **Given** 双屏分别选择IP81和窗口1，**When** 点击应用，**Then** 发送这一组合，保留每次切墙重发音量的既有规则。
3. **Given** 输入未登记或发送失败，**When** 应用，**Then** 显示具体失败原因，不伪装成实体画面已成功，也不自动重试。
4. **Given** 其它客户端或主机连接发生变化，**When** 旧请求稍后返回，**Then** 不借用其它布局的修订号下发、不向新主机补发旧操作。

### User Story 2 - 按现场任务组织控制台 (Priority: P1)

操作人员在统一 Ant Design 界面中，先看两路播放器，再完成墙面分配；媒体、摄像机、音频及预设各有清晰工作区，配置和危险操作不混进常用操作。

**Why this priority**: 单纯替换控件不能解决导航分散与页面层级不清。

**Independent Test**: 在桌面和手机从控制台分别进入窗口、媒体、摄像机、预设和设置，完成主要操作且可返回；页面布局和组件均实际更新。

**Acceptance Scenarios**:

1. **Given** 打开工作台，**When** 查看页面，**Then** 两路输出和布局操作形成主要操作区，系统音量和设备电源位于次级区，不堆砌无用统计卡。
2. **Given** 进入媒体或预设，**When** 浏览目录、搜索、筛选或批量选择，**Then** 目录、内容和所选对象操作层级清晰，保留真实路径与只读内置目录。
3. **Given** 进入摄像机与音量，**When** 选择摄像机或音量来源，**Then** 摄像机选取、云台及音频控制分区明确，危险/不可用操作仍有相应限制。
4. **Given** 打开任意主页面，**When** 切换明暗主题或缩窄窗口，**Then** 组件、导航、弹层、表单与通知保持一致，不残留另一套组件外观。

### User Story 3 - 保持现有功能和安全边界 (Priority: P2)

在更易操作的页面中继续使用上传、移动、删除、直播流、PPT、共享、音频、预设、登录及主机设置，不因视觉重构丢失功能或发生额外设备动作。

**Why this priority**: 中控重构必须可用，不能交付只可浏览的静态外壳。

**Independent Test**: 用本机受控接口完成全部主路由及关键弹层的回归，验证事件只发一次、失败可见、离页不会触发设备操作。

**Acceptance Scenarios**:

1. **Given** 选择媒体或上传资源，**When** 目录变化、批量操作或打开到窗口，**Then** 保持当前目录、受保护资源规则、删除确认与目标窗口身份。
2. **Given** 输入或移动滑杆，**When** 用户提交，**Then** 原节流与提交语义不变；云台按住/释放及失焦停止保持。
3. **Given** 登录、连接或请求失败，**When** 查看反馈，**Then** 表单标签、错误、重试和键盘焦点可用，不以删除状态提示为由隐藏真实错误。
4. **Given** 已完成一次请求，**When** 弹层关闭或页面切换，**Then** 不新增重复请求、未释放订阅或控制台异常。

### Edge Cases

- 两侧都不映射、空名称、非法IP、未登记设备流：拒绝下发并说明原因。
- 应用期间重复点击或修改选择：仅一笔操作，按点击时的明确布局执行。
- 预检和发送之间有其它客户端更新：拒绝旧修订，不自动替换或重发。
- 离页、退出或切主机：不展示旧成功、不向另一连接继续发送。
- 已有未确认发送状态：不在仪表盘显示用户要求删除的常驻状态/详情，后台诊断及错误语义不删除。
- 360px手机、长路径/文件名、暗色、键盘与减少动效：主要操作可达、没有页面横向溢出。

## Requirements

### Functional Requirements

- **FR-001**: 首页只提供一个“应用布局”主操作，编辑后无需用户保存草稿；设置中的共用布局块保持同一操作方式。
- **FR-002**: 选择、进入页面和往返单双屏不得自行下发物理命令；应用仅处理本次明确选择，失败不自动重试。
- **FR-003**: 删除草稿徽标、发送状态、发送详情、上次发送布局与“控制帧已写出；尚无与本次操作关联的实体画面确认”的常驻展示。
- **FR-004**: 保留读取、忙碌、无效输入及失败反馈，不把请求完成描述为实体画面已确认。
- **FR-005**: 保持现有12种组合、自定义设备流预检、版本冲突保护、切墙重发音量与仅两个播放器的约束。
- **FR-006**: 全部主页面、弹层、导航、主题、表单和通知采用一致的 Ant Design 组件与视觉语言，不同时运行两套组件系统。
- **FR-007**: 参考至少两个同类开源项目的实际前端，记录来源与采用/不采用理由；不得仅替换控件并原样保留旧排布。
- **FR-008**: 工作台以两路输出和墙面编排为核心，辅助声音和设备操作形成次级区域；媒体、播放、摄像机音量、预设和设置分别整理布局。
- **FR-009**: 保持全部现有路由、媒体目录、固定摄像机、批量操作、PPT、共享、预设、音频与账户功能，不改后端协议和设备绑定。
- **FR-010**: 360px及以上无页面横向溢出；手机主要触控目标至少44px；键盘焦点、标签、暗色及减少动效保持可用。
- **FR-011**: 自动回归与真实本机浏览器覆盖主路由、直接应用、失败、弹层、响应式及控制台错误；本机验证不得对现场设备发包。
- **FR-012**: 更新使用、维护、设计约定和变更文档；未部署的本机结果不得宣称D4已更新。

### Key Entities

- **本次布局选择**：用户选择的单/双屏、区域输入与可选地址，应用期间冻结。
- **操作结果**：请求完成、失败或正在处理；不表示未经观测的实体画面。
- **任务工作区**：工作台、窗口、媒体目录、摄像机与声音、预设、设置；仅重组展示，沿用现有数据归属。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 全部12种基础布局均可编辑后一次点击提交；页面中保存草稿和发送详情入口为0。
- **SC-002**: 全部主路由与关键弹层可实际操作，旧组件系统的生产依赖与控件引用为0。
- **SC-003**: 桌面1440px、平板1024px与手机390/360px验证无页面横向溢出，关键操作可达。
- **SC-004**: 直接应用、重复点击、未登记流、版本冲突及换主机/离页的回归全部通过，物理发包为0。
- **SC-005**: 主题、目录、播放和设备操作的关键浏览器流程无未处理异常，已有功能没有因控件事件差异漏发或重复。

## Assumptions

- 使用现有Vue共享前端对应的Ant Design实现，不改为另一种前端框架，不新增付费依赖。
- “直接应用”指一次明确点击，而不是选项一变就发设备命令；内部安全预检仍保留。
- 本轮先在本机完成并按仓库约定保存本地提交；远端推送、D4部署或实体切墙不由本次界面修改自动触发。
- 新需求覆盖009/013中关于手动保存及旧界面视觉的冲突描述，底层安全约束继续有效。
