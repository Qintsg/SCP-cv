# Feature Specification: 按需共享的免安装直播预览

**Feature Branch**: `main`（沿用当前工作区）
**Created**: 2026-10-20
**Status**: Implemented（本机应用层方案；未推送／部署，现场网络与全机QoS未代验）
**Input**: 用户要求复用D4现有MediaMTX将RTMP转换为HTTP-FLV／WebSocket-FLV；观看端不安装Node／FFmpeg；不能持续拉所有流，同流并发共享上游；预览流量优先级低于正式播放与其它服务，拥塞时降码率／帧率尽量不断。继续仅本机实现，不更改部署。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开网页即可预览 (Priority: P1)

操作者直接在网页查看窗口／输入设备／已登记直播源，不需要在观看电脑安装额外运行时。

**Why this priority**: 解决016可选本机桥造成的现场安装负担。
**Independent Test**: 本机合成流通过共享服务、HTTP-FLV／WebSocket-FLV及网页播放器解码；无现场设备请求。
**Acceptance Scenarios**:

1. **Given** 已认证网页与可用输入，**When** 预览进入可见区域，**Then** 只观看视频即可，用户设备无需Node／FFmpeg，预览无声音。
2. **Given** 没有预览流或预留3/4，**When** 查看卡片，**Then** 普通空态而非报错；真正连接失败只显示卡内状态与一行原因，不弹窗。
3. **Given** 原始RTMP或RTSP流，**When** 进入预览，**Then** 由现场服务转成浏览器支持的FLV，不把源凭据送往浏览器。

### User Story 2 - 只拉正在看的流且合并重复请求 (Priority: P1)

多个操作者查看相同流时，只向设备建立一份上游连接；没有人看就释放。

**Why this priority**: 限制摄像机、网络和服务器资源占用。
**Independent Test**: 并发租约、共享计数、等待首帧取消、隐藏／离页、租约到期及停机的确定性测试。
**Acceptance Scenarios**:

1. **Given** 同一实际流的多个卡片／客户端，**When** 并发订阅，**Then** 共享一份上游及一份转码输出，不按客户端重复拉流。
2. **Given** 最后一位观看者离开，**When** 宽限期和租约到期，**Then** 停止自有转换并释放上游；无人观看时没有轮询全部设备。
3. **Given** 不同凭据、不同通道或源修订，**When** 订阅，**Then** 不错误共享为相同流；旧关闭不得取消新订阅。

### User Story 3 - 预览让路且拥塞可降档 (Priority: P1)

正式播放和其它业务优先，预览有独立总量预算；慢观看端不拖住所有人，网络变差时优先降低预览质量。

**Why this priority**: 预览不能影响大屏正式播放或耗尽网络。
**Independent Test**: 假时钟／受控带宽／慢消费者与真实合成解码验证，记录可保证与系统级限制。
**Acceptance Scenarios**:

1. **Given** 多流／多客户端，**When** 总预览流量上升，**Then** 全部预览出站不超过可配置预算，排队／缓存有界。
2. **Given** 慢观看端或持续拥塞，**When** 需要追赶直播，**Then** 从可解码关键帧追赶，不随机丢字节；降码率／帧率先于主动断开，保留最后可用画面并如实显示连接状态。
3. **Given** 正式直播播放或主机网络繁忙，**When** 分配预览资源，**Then** 使用保守档位和独立低优先级预算，不提高正式播放负担；不把CPU优先级误称全机网络优先级保证。

### User Story 4 - 预览也遵循认证与停机边界 (Priority: P2)

只有本人有效会话可使用已许可输入；预览不能变成任意网络代理，也不能留下无主进程。

**Why this priority**: 服务端拉流扩大了可访问网络范围，必须限制能力。
**Independent Test**: 正式认证／防跨站／源解析／限额／终止测试，默认不启动实体服务。
**Acceptance Scenarios**:

1. **Given** 无认证、跨站、过期或他人租约，**When** 观看或续租，**Then** 拒绝且不启动上游。
2. **Given** 任意外部URL、预留输入或无效IPv4，**When** 创建预览，**Then** 不发起连接；只接受已登记媒体或明确墙面设备输入。
3. **Given** 停机、退出或服务异常，**When** 清理，**Then** 仅清理本实例拥有的转换器与路径，不重启MediaMTX、不影响正式发布流或其它进程。

### Edge Cases

- 同流首帧等待中65个并发订阅、取消／重新打开、源被编辑或删除。
- MediaMTX离线、API失败、转码依赖缺失、无效FLV／超长tag、源断流后恢复。
- 新订阅中途加入、降档编码重启、时间戳回绕或变更、慢客户端缓存追赶。
- 摄像机不提供低清、原始流本身占满入站链路：输出降码率不会降低上游原码流；界面与文档必须如实说明。
- 交换机不识别优先级、服务同一HTTPS连接复用：应用层预算可落实，不能承诺任意网络上绝对低于所有其它流量或永不断线。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 提供HTTP-FLV与WebSocket-FLV预览，观看端无额外工具依赖；复用现有MediaMTX，不创建第二个常驻实例。
- **FR-002**: MUST 只在有有效观看需求时拉流；同一规范化实际URI共享一份上游与转码，多客户端不重复拉源。
- **FR-003**: MUST 默认小窗低清通道、无音轨，高清只在需要时使用；3/4不猜输入。
- **FR-004**: MUST 对可见／隐藏、取消、离页、失联到期、Host停机进行所有权明确的回收；无观众后有限宽限期释放。
- **FR-005**: MUST 配置全局预览出站带宽、上游数、订阅数及缓存上限；对预览实行低资源优先策略，不修改正式播放的队列和码流设置。
- **FR-006**: MUST 在拥塞时优先降输出码率／帧率并从完整关键帧组追赶；有恢复迟滞，不随机丢FLV字节或无限排队。
- **FR-007**: MUST 如实说明入站原码流、全机QoS与编码不兼容的限制，不承诺永不间断；源失败时保留最后画面但明确不是实时。
- **FR-008**: MUST 沿用会话、防跨站与主机归属保护；租约不可被另一用户／认证代次复用；WebSocket核对Origin，浏览器不接收上游凭据。
- **FR-009**: MUST 只接受媒体ID或受限墙面输入描述，不提供任意URL代理；私有MediaMTX API仅服务端访问，路径仅清理本实例所有项。
- **FR-010**: MUST 去除生产界面对用户本机桥的依赖与配置，不长期保留两套预览实现；失败仅内联，无流为空态。
- **FR-011**: MUST 更新OpenAPI、配置、使用／维护文档，按分层测试验证，默认测试无实体副作用；本轮不部署／连接D4。

### Key Entities

- **预览输入**：已登记媒体或墙面设备来源，含清晰度意图；实际连接地址仅服务端可见。
- **共享流**：相同实际地址与凭据的唯一拉流／编码生命周期，拥有路径、质量档位及有界可解码缓存。
- **观看租约**：绑定认证身份及代次，有限生存期、单消费者连接，支持续租和关闭。
- **资源预算**：预览总出站速率、流数量、缓存及拥塞档位，不是正式播放配额。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 合成源在HTTP与WebSocket两通道均可持续解码；访问端仅浏览器，未安装本机桥也能查看。
- **SC-002**: 65个同流并发请求只启动1份上游和1份编码，关闭所有租约后不超过35秒停止拉流；无租约时上游数0。
- **SC-003**: 受控慢客户端不阻塞其它观看者，缓存不超配置上限；出站在允许单次分块突发外不超预算，拥塞先降档，恢复不频繁震荡。
- **SC-004**: 未授权／跨站／过期／任意URL场景均0上游连接，源凭据在公开响应和错误中出现次数0。
- **SC-005**: 本轮现场请求、实体控制与远端变更均0；验收明确区分本机合成流与现场带宽／出画。

## Assumptions

- 用户新指令替代016“必须用户本机直拉”的约束；允许将预览经D4转发，但尚不授权改变部署。
- MediaMTX本身不提供FLV输出，需一层受控转换；服务器可以依赖FFmpeg，不要求观看端安装。
- 优先落实可证明的应用层限速与降档；全机网络绝对优先级需要额外Windows／网络设备QoS支持，单靠播放器无法保证。
- 摄像机通道0／1按既有高清／低清约定；普通已登记直播源不擅自改路径或凭据。
- 只有显示且页面可见的预览续租，后台不持续拉全库。
