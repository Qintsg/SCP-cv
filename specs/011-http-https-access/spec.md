# Feature Specification: 网页双协议入口与共享安全跳转

**Feature Branch**: `main`

**Created**: 2026-10-12

**Status**: Implemented — 本机验证完成，未部署D4

**Input**: 用户要求允许 HTTP/HTTPS，地址无协议时默认 HTTP；HTTP 页面共享前确认跳转 HTTPS。证书由用户提供，不自动导入根证书。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 普通操作默认明文入口 (Priority: P1)

用户通过 HTTP 使用登录、媒体管理、播放控制和状态更新；明确填写 HTTPS 时使用加密入口，不擅自更改协议。

**Why this priority**: 无域名或可信证书时仍能执行普通现场控制。

**Independent Test**: 输入裸主机地址、明确 HTTP 和 HTTPS，分别检查连接地址；通过 HTTP 登录和执行受权限保护的普通操作。

**Acceptance Scenarios**:

1. **Given** 无协议的主机和端口，**When** 连接，**Then** 补 HTTP，保留主机和端口。
2. **Given** 明确 HTTPS 地址，**When** 连接，**Then** 保持 HTTPS，证书错误不自动降级。
3. **Given** 两入口均配置，**When** 分别访问，**Then** 页面、认证和状态更新可用。

### User Story 2 - 共享前确认安全跳转 (Priority: P1)

用户在 HTTP 点击共享时，先看到 HTTPS 必要性、自签证书警告及可能重新登录的说明，再决定是否跳转。

**Why this priority**: 普通控制不需要可信证书，采集仍遵守浏览器安全要求。

**Independent Test**: 在窗口1/2分别取消、确认提示，检查地址、当前页面和零自动采集；HTTPS 页面再次主动点击后才开始原有共享流程。

**Acceptance Scenarios**:

1. **Given** HTTP 页面（包括本机地址），**When** 点击共享，**Then** 显示确认，不采集、不预约共享、不改变播放器。
2. **Given** 提示已打开，**When** 取消，**Then** 保留页面和状态，焦点返回按钮。
3. **Given** 已配置安全入口，**When** 确认，**Then** 使用同一网页主机的明确安全端口，保留合法页面位置；不在链接中传递认证秘密。
4. **Given** 未配置或无法读取安全入口，**When** 确认，**Then** 明确提示不可用，不猜端口、不开始采集。
5. **Given** 刚跳转 HTTPS，**When** 页面加载，**Then** 正常认证，必须再次主动点击共享，不自动打开选择器。

### User Story 3 - 两协议来回访问不串会话 (Priority: P2)

同一用户可以同时使用两入口，并在两入口之间切换，不覆盖另一入口的认证状态。

**Why this priority**: 避免使用 HTTPS 共享后 HTTP 控制失效。

**Independent Test**: HTTP → HTTPS → HTTP 登录及写操作、独立注销和并发状态请求，明确核验两入口的会话隔离。

**Acceptance Scenarios**:

1. **Given** 两入口已登录，**When** 在 HTTPS 注销，**Then** 不删除 HTTP 会话，反向亦然。
2. **Given** 并发访问，**When** 收到状态和执行写操作，**Then** 请求使用各自认证与防伪令牌。
3. **Given** 端口冲突或错误的前端TLS证书配置，**When** 启动，**Then** 明确失败，不随机换端口、不留下半运行服务。

### Edge Cases

- 相同端口、被占用端口、无证书、部分证书配置、SAN不匹配和不受信任的证书。
- 裸 IPv4/DNS/带方括号 IPv6；拒绝其他协议、凭据、路径及秘密参数作为主机地址。
- 离线、未登录、封装端不支持采集；多次点击只出现一个确认。
- 等待入口信息时切换账号、主机、页面或组件卸载，不迟到跳转。
- 当前页面敏感参数不能复制进新链接；跨主机连接不得悄悄改为另一播放主机。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 网页普通功能 MUST 允许 HTTP，未指定协议的主机地址 MUST 默认 HTTP；明确 HTTP/HTTPS MUST 保持原样。
- **FR-002**: 配置证书后 MUST 同时保留两网页入口；加密入口及其加密上游 MUST 正常校验证书，错误的前端TLS配置 MUST 拒绝启动，上游证书错误 MUST 拒绝请求而不回退HTTP。
- **FR-003**: HTTP 共享按钮 MUST 只触发确认；确认前和导航后未再次主动点击前，采集及共享写请求数 MUST 为零。
- **FR-004**: 确认 MUST 说明安全连接、证书可能未信任及可能重新登录；取消 MUST 无导航或播放器副作用。
- **FR-005**: 导航 MUST 使用实际配置的安全端口、相同网页主机及合法页面位置，不传递密码、会话、防伪或接收能力令牌；不存在入口时 MUST 明确失败。
- **FR-006**: HTTP/HTTPS 认证、防伪与注销 MUST 按协议隔离；HTTPS 会话 MUST 保持安全属性，不能以降低所有 Cookie 保护实现明文入口。
- **FR-007**: 已有共享安全门禁、独占两窗、真实释放证明和私有接收页 MUST 保持，不改变墙面、电源或媒体行为。
- **FR-008**: 用户证书/私钥 MUST 留在私有目录，不进入源码、网页资源、日志或分发构建；系统 MUST 不自动安装根证书。
- **FR-009**: 页面 MUST 提醒 HTTP 不加密账号和控制数据；本轮网页双入口不扩大封装端明文认证或移动屏幕采集支持范围。
- **FR-010**: 生命周期取消、离线、错误入口信息和快速重复点击 MUST 有明确结果，不允许迟到跳转或绕过原主机身份。

### Key Entities

- **网页入口**: 协议、主机、端口；一个普通入口和可选安全入口，共享页面内容。
- **入口会话**: 所属协议、用户与防伪状态；不同协议互不覆盖。
- **跳转确认**: 当前页面、所属主机/账号寿命、确认/取消/失败结果，不持久化采集授权。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 裸地址、明确 HTTP/HTTPS 和非法地址验收样例全部符合指定协议与拒绝规则。
- **SC-002**: 两窗口的取消、确认、重复点击、缺少入口、迟到结果场景中，跳转前采集和共享写操作均为零。
- **SC-003**: 两协议三次来回切换及并发请求中，登录、写操作、状态更新与独立注销全部成功，无会话覆盖。
- **SC-004**: 桌面/窄屏、浅色/深色提示能完整阅读并通过键盘操作，无横向溢出和新增页面异常。
- **SC-005**: 配置错误与端口冲突样例全部明确失败；构建产物中证书和私钥泄漏数量为零。

## Assumptions

- 本轮接入现有网页与共享功能；封装客户端仍需要其现有受信 HTTPS 认证策略。
- 默认 HTTP 5173、HTTPS 5174，允许显式配置；不会将同一个端口声明为两种协议。
- 用户提供服务器叶证书及匹配私钥；根信任由用户管理。自签证书不保证浏览器可采集。
- 不自动部署、重启 D4 或修改系统信任；后续部署以用户指令为准。
- 新要求取代010中“普通网页只用HTTPS”的访问描述，010的采集安全要求继续有效。
