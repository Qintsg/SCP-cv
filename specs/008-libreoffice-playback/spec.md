# Feature Specification: LibreOffice 完整只读播放接入

**Feature Branch**: 当前工作区；接入前保存点 `549c57f`

**Created**: 2026-09-29

**Status**: Draft

**Input**: 不走 LibreOffice 源码修改路线；完整接入现有 LibreOffice，把上传转换和播放都交给 LibreOffice，删除 PowerPoint 入口。只需播放、不需编辑；重点多开、切换、关闭稳定性。

## Clarifications

### Session 2026-09-29

- Q: 是否保留实验性PowerPoint入口？ → A: 全部改用LibreOffice，删除PowerPoint入口，上传转换也改LibreOffice。
- Q: 是否接受先接入LibreOffice，并明确禁用尚不支持的统一媒体控制？ → A: 接受。统一媒体暂停/恢复/定位未支持时前端禁用、后端明确拒绝；不以暂停标志或静音冒充能力，关闭和显示稳定性仍须通过。

### Session 2026-10-03

- Q: 动画播放期间再次点击下一步应如何处理？ → A: 快速完成当前动画后下一步，类似普通情况下的PPT放映；不得仅等待动画自然结束或吞掉这次推进。
- Q: 最后一页且后续动画也已耗尽，再下一步应如何处理？ → A: 实际无播放动作，保持最后一页画面，前端提示“当前已是最后一页”；末页尚有动画时仍允许推进，不进入黑色结束屏或清空窗口。
- Q: 后续D4测试与环境安装范围？ → A: 可以继续在D4窗口1/2及D:/SCP-cv进行项目测试、更新并安装相关环境；尽量不再询问，原件/进程归属与未知墙面协议保护仍保持。

### Session 2026-10-04

- Q: 稳定性与PPT兼容性如何取舍？ → A: 稳定运行优先，少量PPT限制或轻微显示缺陷可以接受；必须明确记录并提示，不以崩溃、卡死、退出残留、误操作或假成功换取兼容性。
- Q: 后续优化是否只围绕PPT？ → A: 否，同时优化前端并检查其它已支持媒体源，覆盖真实交互、显示、后端调用及多源切换；不能用PPT单项验证替代整体检查。

## User Scenarios & Testing

### Session 2026-10-01补充选择

- 用户选择“加入可选的文字适配，默认保持原排版”。关闭兼容选项时不主动缩小文字；开启后只在内存中让文字适应原框，不保存或修改原件。动态放映和显式转换采用相同规则，并明确标识所用布局，不静默替换默认制品。

### User Story 1 - 两窗只读动态播放 (Priority: P1)

用户在窗口1/2打开原文稿，保留受支持的动画和多媒体，播放器不露出编辑器界面或改变原件。

**Why this priority**: 动态内容及纯播放是替换引擎的核心价值。

**Independent Test**: 两窗同/异文稿并存，动画步进、直接跳页、媒体控制与实际画面/状态分别核对。

**Acceptance Scenarios**:

1. **Given** 可读取文稿和已就绪播放依赖，**When** 打开，**Then** 仅目标窗口出画，页数/当前页真实，菜单、导航、编辑和保存入口均不可用。
2. **Given** 带点击动画及音视频的文稿，**When** 动画步进或换页，**Then** 两种动作语义分开，实际状态回传；指令受理不能冒充动画或解码已完成。
3. **Given** 正在播放的媒体但引擎未验证统一媒体暂停/恢复/定位能力，**When** 查看或调用控制，**Then** 前端禁用并说明限制，后端明确unsupported且不产生副作用；关闭文稿仍必须停止其媒体并取得退出证据。将来声明支持的动作必须以真实媒体时钟和画面验收，不以静音或放映暂停标志替代。
4. **Given** 引擎不支持某动作，**When** 发起操作，**Then** 明确失败/禁用并说明能力，不伪造成功或悄悄降级为图片。
5. **Given** 当前点击动画正在播放，**When** 用户再次点击下一步动画，**Then** 快速完成当前动画并推进下一步；没有正在播放的动画时推进下一步，不能丢失已受理的点击、跳过未请求的效果或用固定延迟冒充完成。
6. **Given** 当前为实际放映末页且没有剩余动画，**When** 再次请求下一步，**Then** 不推进原生效果/切页、不黑屏或清空，前端提示“当前已是最后一页”；末页未完成的动画仍可正常推进，回退/重开后重新判定，不沿用旧完成状态。

### User Story 2 - 原件上传与静态预览 (Priority: P1)

用户上传PPT/PPTX后原件按页面目录存储，并可得到页数、预览和显式静态回退，不依赖PowerPoint。

**Independent Test**: 原件SHA不变，转换成功/失败/超时可诊断，已存在页图不阻断动态原件播放。

**Acceptance Scenarios**:

1. **Given** 原件上传到中文目录，**When** 转换，**Then** 原件保留，页图与原件摘要/修订关联，文件移动后关联仍正确。
2. **Given** 原件存在但预览缺失，**When** 动态打开，**Then** 不因静态页图状态被错误拒绝；静态回退未准备时明确不可用。
3. **Given** 转换失败或结果不确定，**When** 查看/重试，**Then** 状态真实，不能盲目重复不确定的外部操作。

### User Story 3 - 稳定生命周期和故障隔离 (Priority: P1)

反复多开、切换与关闭时，一窗操作不污染另一窗，不控制用户已有LibreOffice文稿。

**Independent Test**: 本机及已授权D4的10轮同/异源多开替换关闭、100次控制、有界故障注入和精确退出/文件锁；D4软件测试与相关环境安装已授权，现场物理动作不据此泛化。

**Acceptance Scenarios**:

1. **Given** 两独立播出实例，**When** A反复换源/关闭重开，**Then** B的源、页、媒体保持独立。
2. **Given** 旧组或旧文稿的命令/结果，**When** 新实例启动，**Then** 旧意图不重放、旧结果不改写新画面。
3. **Given** 引擎卡住/崩溃/失联，**When** 观察或关闭，**Then** 明确错误/不确定，记录精确归属，有限清理只作用于自有成员。

### User Story 4 - 配置、控制台和文档一致 (Priority: P2)

用户看到新的默认引擎、依赖就绪与能力提示，不再看到PowerPoint实验性入口。

**Independent Test**: 桌面/手机界面、HTTP合同和运行组与当前需求一致；旧入口不能继续启动PowerPoint。

**Acceptance Scenarios**:

1. **Given** 缺失/不兼容依赖，**When** 查看设置或打开，**Then** 明确显示原因及配置方式，不标成播放成功。
2. **Given** 旧PowerPoint请求，**When** 调用，**Then** 明确退役，不变成另一个有副作用的新动作。

### User Story 5 - 稳定且一致的多源控制 (Priority: P1)

操作员需要可靠的控制台和各类媒体输出，而不只是一种文稿的兼容演示。

**Why this priority**: 实际使用需要各类源反复切换、失败可诊断、两窗互不影响；PPT边缘特性不应长期独占整体优化。

**Independent Test**: 桌面和手机分别操作图片、PDF/页图、视频、网页、已有直播类型及背景音频，并核实际输出、状态和退出。

**Acceptance Scenarios**:

1. **Given** 已知少量PPT不支持特性或轻微版式差异，**When** 上传或打开，**Then** 明确告知受限内容及适用范围；危险特性必须安全拒绝或经验证的受限播放，原件保留，静态回退需用户明确选择，不能静默删动画或泛化为全部PPT不可用。
2. **Given** 正在切换媒体或打开失败，**When** 查看控制台，**Then** 期望源、实际输出、待处理与错误可辨识，参考缩略图不冒充真实出画；按钮能力、错误和后续反馈与当前实际状态一致。
3. **Given** 任一已支持源类型，**When** 执行登记/上传、编辑、打开、相应控制、切换或关闭，**Then** 前端请求、持久结果及真实画面分别可验证；缺外部源的项目单列未验证，不以在线探测替代解码出画。
4. **Given** 桌面或手机控制台，**When** 正常、空、加载、错误、离线或重连，**Then** 信息可读、主要控件可操作，无横向遮挡或旧提示污染；重复网络事件不重复执行外部动作。

### Edge Cases

- 旧PPT、损坏/加密文稿、大媒体、缺字体、原件暂失、中文目录和活跃文件移动。
- 本机用户LibreOffice已打开、启动器脱离父树、PID复用、旧端口/profile残留。
- 媒体仍播放但放映paused=true；菜单隐藏后重新出现；父窗口/DPI/显示目标改变。
- 转换结果晚到、关闭/切源在途、停止失败、应用退出后DLL或文稿仍锁定。
- 少量已知PPT不支持特性、轻微版式差异，以及失败后明确选择静态回退；不能静默删动画或修改原件。
- 图片、PDF/页图、视频、网页、直播及独立背景音频的交叉切换；前端期望源与实际输出不同、离线/重连与旧响应。

## Requirements

### Functional Requirements

- **FR-001**: MUST 先保留当前代码保存点，不删除原件、数据库或既有证据。
- **FR-002**: MUST 使用免费现有LibreOffice/官方互操作路线，不修改/编译其源码、不购买商业许可。
- **FR-003**: MUST 完全退役PowerPoint上传转换/播放/设置入口，原PPT/PPTX仍保留。
- **FR-004**: MUST 仅提供两窗只读播放，无编辑/保存/宏执行/自动更新外链，不占控制桌面。
- **FR-005**: MUST 真实支持并区分动态播放、静态预览/手动回退及其各自可用条件。
- **FR-006**: MUST 明确动画步进、换页、媒体控制语义；当前允许统一媒体暂停/恢复/定位不支持，但MUST通过capabilities向前端禁用、后端明确unsupported，禁止调用原生接口后伪报成功。其他音量/静音控制仅在真实能力验证后启用，不以受理或暂停标志假报成功。
- **FR-007**: MUST 独立归属每窗与转换实例；只控制自有文稿/进程/profile，不按进程名全局关闭。
- **FR-008**: MUST 对组、所有者、引擎、文稿和源修订进行隔离，超时不能证明未执行，不确定动作不得盲重放。
- **FR-009**: MUST 修复确认停机后Pending旧意图可被新组领取的安全前置；保留最后实际观测，不伪造完成。
- **FR-010**: MUST 保持用户目录存储、原件摘要、移动/删除一致性及转换关联。
- **FR-011**: MUST 不重新引入Python生产服务，原型中的Python仅作验证工具。
- **FR-012**: MUST 更新合同、配置、运行脚本和用户/维护文档，并记录不支持和实机未验证内容。
- **FR-013**: MUST 提供默认关闭的文字适配选项；开启才允许在内存中缩放文字适应原框，保持原件摘要不变。该选项不承诺对所有字体和版式完全保真，所用模式与静态制品关联必须可辨识。
- **FR-014**: MUST 对动画中再次发出的下一步请求执行“快速完成当前动画后推进下一步”；空闲时仅推进下一步。重复网络事件防重与用户的多次明确点击应分开，不吞已受理请求，不以固定等待、命令返回次数或事件计数制造步序完成证明。
- **FR-015**: MUST 在实际放映末页且动画耗尽时将下一步作为无播放副作用的边界结果，保持最终画面/实际源/页码，前端提示“当前已是最后一页”。末页尚有动画、倒退/跳页/重开/换源后不能误用旧完成事实，不能仅按页码或调用次数推测动画已耗尽。
- **FR-016**: MUST 优先保证稳定运行。允许少量明确的PPT兼容限制或轻微显示缺陷，但须记录样例、影响和替代操作；已知危险特性必须在危险播放动作前安全拒绝或采用已验证的受限行为，不静默删动画、修改原件或自动回退。崩溃、卡死、退出残留、跨窗污染、数据丢失与假成功不属于可接受的小缺陷。
- **FR-017**: MUST 将前端优化和其它已支持源纳入当前收敛范围，至少覆盖图片、PDF/页图、视频、网页、RTSP/SRT/自定义直播及独立背景音频的相关操作与混合切换。前端须区分期望/实际输出和参考预览；真实桌面/手机交互、后端调用与实体出画分别验收，不新扩展格式或自动重放不确定动作。

### Key Entities

- 播放依赖：安装路径/版本、互操作就绪、能力与失败原因。
- 引擎实例：目标窗、不可变身份、自有profile/进程、代次和生命周期。
- 文稿实例：原件/摘要/修订、页码、动画及媒体状态、清理状态。
- 转换作业：原件修订、准备状态、产物关联、失败/不确定与人工重试。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 无PowerPoint进程/依赖调用即可完成原件上传转换与两窗动态播放；旧入口有明确退役结果。
- **SC-002**: 本机及D4的10轮两窗交叉换源、关闭重开及100次控制有实际完成数、状态/图像/文件锁证据；失败不隐藏，不把本机小窗等同D4两输出。
- **SC-003**: 未支持的统一媒体控制在前端禁用、后端明确拒绝且无原生副作用；所有声明支持的媒体动作以真实时钟/画面验收，关闭后媒体不继续运行，不能只有布尔字段通过。
- **SC-004**: 关闭后自有进程/监听/窗口消失，原件摘要不变，用户已有应用不被清理。
- **SC-005**: 自动化、合同和真实界面门禁通过；缺外部条件时逐项记录，不将仿真或本机冒充D4验收。
- **SC-006**: 每种既有源有独立操作/失败/切换/关闭记录，桌面和手机至少各一轮主要流程；双窗混合源完成10轮切换及至少60分钟观察。每个已接受PPT限制均有明示行为及不崩溃/可正常关闭证据，不能仅据少量限制被允许而免除稳定性门禁。

## Assumptions

- 自2026-10-03最新授权起可在D4窗口1/2、D:/SCP-cv进行相关环境安装和项目软件实测；先核当前进程、交互会话和输出绑定，原件/数据库保留。此授权不自行扩展到电源、未知墙面映射或系统音量；历史“仅本机/D4暂停”记录保留为当时范围。
- 页图/PDF保持明确手动回退；不可在动态失败后静默宣称全部动画媒体已播放。
- 先完成互操作、纯播放承载、关闭稳定性门禁；用户已接受未支持的统一媒体控制明确禁用，不再阻断接入。该选择不豁免纯净画面、退出和其它声明支持能力的实证要求。
- 用户最新引擎替换决定取代旧宪章中固定PowerPoint角色约束；进程隔离、fencing、验证和安全原则仍适用，治理文件需独立同步。
- 2026-10-04接受的小限制不是放弃末页规则、正常动画、多开/切换/关闭、原件保护或真实性要求；可接受的轻微差异不追求逐像素保真，但内容可读且影响须明示。未记录/未验证的缺陷不能自动视为已接受。
