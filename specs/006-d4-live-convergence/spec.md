# Feature Specification: D4 大屏实机收敛与优化

**Feature Branch**: `main`（本仓库未配置 Spec Kit 建分支 hook）

**Created**: 2026-09-27

**Status**: Draft

**Input**: User description: "完成所有内容的优化；允许在 D4 的窗口 1/2 上测试、操作对应窗口进程，以及操作 D:\\SCP-cv 中的文件和数据库。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 两块大屏可靠播出 (Priority: P1)

现场操作员在控制台给窗口 1、2 打开不同媒体，切换两个已知墙面预设，看到左、右输出持续显示预期内容。播放器不得占用控制桌面或小电视输出；旧窗口 3/4 的请求仍明确拒绝。

**Why this priority**: 这是现场最基本的播出能力，也是先前本机测试无法证明的部分。

**Independent Test**: 在 D4 交互桌面观察两个输出的画面、窗口进程和控制状态，依次切换“窗口 1 全屏”与“窗口 1 左／窗口 2 右”并恢复。

**Acceptance Scenarios**:

1. **Given** 两块大屏输出可用，**When** 分别在窗口 1、2 打开图片、视频、网页和文稿，**Then** 显示器、实体画面及控制状态一致，互不串台。
2. **Given** 双窗预设已显示，**When** 切到窗口 1 全屏再恢复双窗，**Then** 墙面实体画面与活动预设一致；切换失败时不假报成功。
3. **Given** 运行组经历启动、媒体切换与停止，**When** 查看进程和显示器占用，**Then** 始终只有两个播放器，停止后均退出且控制桌面保持可用。
4. **Given** 尚未掌握笔记本或自定义 IP 流的新映射帧，**When** 保存并尝试应用该手动布局，**Then** 仅可预览意图，实体墙面不收到猜测控制帧。
5. **Given** 有可用的现场流地址，**When** 操作员在控制台添加并打开直播源，**Then** 可选择协议、看到连通或失败原因，并在目标窗口看到正确画面。

---

### User Story 2 - PPT 原件安全转换与默认页图播出 (Priority: P1)

操作员从控制台上传 PPT/PPTX，等待逐页图片准备完成后在任一大屏窗口打开、翻页、关闭。默认播放不得启动 PowerPoint 放映；需要原生效果时，可显式启用标明实验性的设置并获得真实失败信息。

**Why this priority**: 本机单元测试不能覆盖 D4 的 Office、显示器和工作进程协作。

**Independent Test**: 使用真实多页测试文稿验证原件、页图、画面、页码、Office 进程所有权与失败重试。

**Acceptance Scenarios**:

1. **Given** 多页文稿上传成功，**When** 转换完成，**Then** 原件和每页图片均可检索，第一页与后续翻页的实体画面、页码一致。
2. **Given** 实验开关关闭，**When** 播放或重开文稿，**Then** 不出现 PowerPoint 放映窗口，播放关闭后页图进程资源被释放。
3. **Given** 实验开关显式开启，**When** 在窗口 1 或 2 打开原件并关闭，**Then** 原生放映只影响目标窗口，自有 Office 资源被清理，用户文稿不被误关。
4. **Given** 转换失败、中断或原件移动，**When** 用户查看状态、重试和再次播放，**Then** 不把未完成作业标为可播放，已准备页图关联仍正确。

### User Story 3 - 媒体源与文件夹可安全整理 (Priority: P1)

操作员在页面上创建、重命名、移动文件夹并上传或移动媒体。D4 的真实文件系统路径与页面一致；下载和播出仍是同一份内容，不覆盖已有数据。

**Why this priority**: 路径不一致会让现场维护、备份和播放失败难以诊断。

**Independent Test**: 在 D4 实际媒体目录执行根目录、中文多级目录、同名文件和跨目录移动，核对原件字节、下载及播放。

**Acceptance Scenarios**:

1. **Given** 用户选择文件夹上传，**When** 上传完成，**Then** 原件位于页面对应目录，重复文件名不覆盖现有原件。
2. **Given** 文件夹含已准备文稿，**When** 移动源或整棵文件夹，**Then** 新路径、下载内容、页图和再次播放均保持有效。
3. **Given** 媒体正在播出、转换中或目标路径冲突，**When** 用户请求移动，**Then** 操作明确拒绝或安全命名，不留下数据库与文件路径不一致的成功状态。
4. **Given** 升级前的媒体和数据库，**When** 部署本轮代码，**Then** 未经用户选择的历史内容不会因升级自动删除。

### User Story 4 - 可观察的长稳与故障恢复 (Priority: P1)

维护人员在 D4 上完成多源切换与持续运行，能够凭画面、状态、日志和进程信息判断真正播出，而不是只凭接口受理成功；发现故障后修复并复测。

**Why this priority**: 先前回归暴露过状态“成功”但物理画面、音量或 Office 资源不一致的风险。

**Independent Test**: 运行多类媒体交替播放与持续循环，注入可恢复的失联/停止场景，记录实际显示和资源趋势。

**Acceptance Scenarios**:

1. **Given** 两窗持续播放混合媒体，**When** 运行至少 60 分钟并执行重复切源，**Then** 无黑屏、错屏、冻结或未报告的进程残留；画面与状态一致。
2. **Given** 播放器失联、Office 作业失败或外部文件缺失，**When** 系统重试或用户恢复，**Then** 状态如实呈现，旧命令不会错误重放到新画面。
3. **Given** 测试期间发现现有功能缺口，**When** 修复并回归，**Then** 自动化、现场画面证据和相应文档同步更新。
4. **Given** 预案指定系统音量，**When** 激活且获准进行音频实体测试，**Then** 实际系统音量与页面一致；硬件写失败时预案不得假报成功。
5. **Given** SRT/RTSP 源进入长稳测试，**When** 独立解码与实体画面检查，**Then** 不持续出现未解释的损坏帧或协议尺寸告警。
6. **Given** 两窗基准测试，**When** 执行常规命令与热切换样本，**Then** 不向退役窗口 3/4 发送测试命令，报告延迟分布及资源趋势。

### Edge Cases

- D4 工作站的现有源、用户文稿及控制桌面可能与测试并存；仅操作能够证明归属的窗口 1/2 进程，不按进程名批量结束 Office。
- 操作 D4 的 `D:\SCP-cv` 文件与数据库已获授权，但移动或删除前仍须核对绝对路径与当前运行组状态；测试不触碰两个小电视的电源。
- 只有既有两个固定墙面预设可以实体下发。笔记本和自定义 IP 流的新帧在独立抓包确认前保持禁止；测试不以猜测控制包补足能力。
- 网络、显示器或 Office 不可用时，明确记录哪个验收项未被证明，不用 Simulation 结果替代现场结果。
- 当前迭代完成现场测试后，若用户没有另行要求常驻服务，应恢复到测试前的停机状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在 D4 交互桌面仅使用窗口 1/2 两个播放器和指定的两块大屏输出，控制桌面和小电视播放输出不被占用。
- **FR-002**: 窗口 1/2 的图片、视频、网页、PDF、PPT 页图及已配置的直播源 MUST 在实际画面和控制状态上保持一致；旧窗口 3/4 的播放请求 MUST 在副作用前拒绝。
- **FR-003**: 两个已知墙面预设 MUST 在 D4 实体画面上正确切换并可恢复；未抓包的手动映射 MUST 只能保存/预览且不得下发猜测帧。
- **FR-004**: PPT/PPTX 上传 MUST 保留原件并产生有序页图；默认播放 MUST 不启动 PowerPoint 放映，实验性原生放映 MUST 仅在显式启用后影响后续打开。
- **FR-005**: PPT 转换、默认翻页及实验性放映的完成/失败状态 MUST 与 D4 的真实画面和 Office 进程一致；用户 Office 文稿不得被误杀。
- **FR-006**: D4 媒体文件夹的上传、重名、源移动、目录移动及下载 MUST 与实体路径和内容保持一致；失败 MUST 不覆盖既有原件或假报成功。
- **FR-007**: 启动、停止、重启和故障恢复 MUST 只管理归属明确的两个播放器，并保留诊断状态；完整测试后按预先约定恢复服务状态。
- **FR-008**: 必须对两窗多源运行、前端交互、后端调用及关键故障路径进行自动化和 D4 实体验证；发现的问题 MUST 修复或明确列出无法验证的外部依赖与风险。
- **FR-009**: 本轮修改 MUST 同步更新需求、任务、用户文档、接口文档、测试证据和已知问题；两台小电视的电源能力 MUST 保留，但本轮不得为测试操作其电源。
- **FR-010**: 已知的预案系统音量假成功、Office 归属不清、视频资源增长以及 SRT/RTSP 损坏/告警 MUST 纳入诊断、修复和同场景复测，不能仅因现有自动化通过而关闭。
- **FR-011**: 操作员 MUST 能通过控制台登记、识别状态并打开支持的直播源；无效地址或解码失败 MUST 有明确反馈，不得伪装为稳定播出。
- **FR-012**: 基准与现场测试入口 MUST 仅以窗口 1/2 为目标，既有四窗操作手册和脚本 MUST 与当前运行组一致，测试至少覆盖普通命令和热切换两类负载。

### Key Entities

- **大屏窗口**：窗口 1 或 2，包含目标显示器、当前媒体、实际画面和进程归属。
- **墙面布局**：已知实体预设或仅保存的手动草稿，包含输入和目标区域。
- **文稿准备作业**：文稿原件、逐页图片、状态及失败原因的关联。
- **媒体文件夹**：页面树节点及 D4 媒体根目录中的对应实体路径。
- **验证证据**：测试条件、命令、画面/状态/进程观察和未通过项的记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: D4 运行组启动、重启与停机各一次，活动播放进程数分别为 2、2、0；窗口 3/4 请求全部被拒绝。
- **SC-002**: 窗口 1/2 的至少图片、视频、网页、PDF、PPT 页图各一次打开/关闭与翻页或进度控制，实体画面、页码和控制状态全部一致；两个墙面预设切换和恢复各一次成功。
- **SC-003**: 至少一份多页 PPT 在 D4 产生与源页数相同的有序图片，默认播放过程中 PowerPoint 放映窗口数为 0；实验开关启停与目标窗口放映各验证一次。
- **SC-004**: D4 根目录与两级中文目录的上传、同名、源移动、目录移动和下载校验全部保持内容摘要不变且无覆盖；失败路径有明确错误。
- **SC-005**: 完成至少 60 分钟两窗混合媒体运行，期间重复切源，无未报告黑屏、错屏或持续资源增长；若出现缺陷，修复后同一场景复测通过。
- **SC-006**: 桌面及手机宽度下的关键页面、设置、源管理和播控路径均无控制台错误或横向溢出；前后端合同与实际返回一致。
- **SC-007**: 预案音量、Office 归属、视频内存和 SRT/RTSP 的已知失败场景各有独立根因、修复或可复现的外部阻因，并在 D4 上按相同条件复测；未通过项不写成已完成。
- **SC-008**: 两窗基准至少包含 1000 次普通写命令与 100 次健康热切换，均无窗口 3/4 请求；记录 p95、最大值、失败数和测试条件。

## Assumptions

- 本功能以 `specs/005-big-screen-only/` 为已实现基线，补齐其 D4 实体验收和发现的缺口，不重新恢复窗口 3/4。
- 用户新授权覆盖 005 中“D4 实体测试暂停”的旧假设：允许更新 D4 的 `D:\SCP-cv`、数据库、媒体及窗口 1/2 的进程和显示测试；不自动扩大到小电视电源或未知墙面帧下发。
- 当前现场仍属开发阶段，允许使用 D4 测试数据；但用户文稿和非项目进程只有归属明确时才可关闭。
- 如果现场网络或设备条件不足，允许先完成其它可验证工作，最后据实记录待现场条件满足的项目，不把未验证项判为完成。
