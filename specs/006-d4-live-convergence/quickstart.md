# D4 两窗实机验证手册

本手册是可执行的验证顺序，不替代 [接口合同](contracts/validation-contract.md) 和 [正式结果](verification.md)。D4 登录及开发账号口令只在交互提示或 ACL 私有文件输入，不写进命令行、仓库或日志。

## 1. 安全前检与快照

1. 在本机确认 `git status --short`、当前提交及两个远端状态。通过当前有效本机 IPv4 地址绑定 SSH 来源；旧文档中的 `192.168.1.104` 不应硬编码，2026-09-27 只读勘察为 `192.168.1.103`。
2. 在 D4 只读确认 `D:\SCP-cv` 的工作区、`ScpCv*`/MediaMTX/PowerPoint 进程、18443/5173/8554/9997 监听、交互会话 ID 及 `D:\SCP-cv\.validation\t129-workstation` 的绝对路径。若存在正在播出的未知实例，先核对归属。
3. 服务停止时，把同一 DataRoot 的 `control.db`、`control.db-wal`、`control.db-shm` 作为一组复制到带时间戳的忽略目录，并记录大小/摘要与媒体目录清单；不得只备份主库，也不在此步骤删除旧文件。
4. D4 使用 `C:\Program Files\Git\cmd\git.exe`（SSH Shell 的 PATH 未包含 Git）从内网 GitLab `origin` 执行 `fetch` 与 `pull --ff-only`；确认 HEAD 与本机推送目标一致且工作区干净。按仓库锁定规则用 D4 .NET 10.0.400 构建，并用 pnpm 验证前端；不用 npm。

## 2. 分阶段启动

1. 用 `runtime-dotnet/scripts/run-headless.ps1` 在 D4 交互会话以 Hardware 模式启动 ControlHost，**先不加** `-StartWorkers`，DataRoot 指向已核对的 `D:\SCP-cv\.validation\t129-workstation`。确认数据库迁移、`/health/ready` 和 `/api/displays/`；只信交互会话返回的真实显示拓扑，SSH 的 `WinDisc 1024×768` 不构成证据。
2. 核对配置 `BigScreenOutputs.Window1/Window2` 的设备名实际对应两块大屏输出，控制桌面不在目标内，再通过受控重启拉起运行组。确认恰好两个 PlayerWorker、AudioWorker、PowerPointHost 及按需 MediaMTX；记录 PID、启动时间和 group epoch。
3. 若墙面电源保持关闭且没有获准开启，暂停依赖实体画面的验收，继续代码、接口和非物理检查；获准开启时只操作拼接屏明确 ON/OFF，结束恢复关闭。**不得切换两台小电视电源。**

## 3. 功能矩阵

1. 窗口 1/2 分别打开图片、视频、网页、PDF、PPT 页图和可用直播源；逐次核对 API 会话、命令完成、目标进程和实体截图。视频测试包括循环、自然结束及相同源重开。
2. 在获准的实体画面条件下切换“窗口 1 全屏”与“窗口 1 左／窗口 2 右”，再恢复测试前预设；另保存笔记本/IP 草稿并确认未支持组合明确拒绝、活动预设不变，不向墙面发送未知包。
3. 上传只读测试文稿副本：比对原件摘要、页数和有序 PNG，默认开关关闭时打开/翻页/关闭并核对没有放映窗口。再显式启用实验模式，分别核对目标窗口的原生打开、关闭、失败报告与用户 Office 保护，最后关闭实验模式。
4. 上传到媒体根目录及两级中文目录；重复同名、移动单个源及整个文件夹，核对 D4 实体路径、下载 SHA-256、页图引用和再次播放。正在播出/转换的移动必须明确失败；单源删除文件占用故障不得假报成功。
5. 检查预案音量、直播源创建/离线恢复、RTSP/SRT 独立解码和实际画面。音量实体测试仅在另行确认后执行，先记测试前值并在结束恢复。

## 4. 稳定性与界面

1. 修订 `runtime-dotnet/scripts/benchmark-commands.ps1` 的窗口目标为 1/2 后，执行 1000 次普通命令、100 次健康热切换，保存原始样本并报告 p95、最大值、失败数。
2. 两窗至少运行 60 分钟混合媒体；每分钟采集实际画面/状态、Worker 私有内存和句柄、Office/MediaMTX 进程、解码错误与日志。因外部源断流导致的失败也要记录，不把它当成通过。
3. 本机真实浏览器用桌面和 390px 手机视口覆盖登录、源/目录、播控、预案、映射与设置；检查布局、控制台错误、失败请求和状态同步。能运行的 Electron/Android 封装端分别验证，不可用时记下条件和风险。

## 5. 收尾

先协作停止运行组，核对两个播放器与自有 Office 均退出，再停止 ControlHost 和测试前原本未运行的前端；确认端口/进程恢复到基线。恢复本轮调整的固定预设和系统音量（若执行），如获准开启过拼接屏则明确关回；电视电源不操作。清理仅限精确登记的本轮测试源和产物。把通过、失败、未执行及原始证据路径写入 `verification.md`，同步现行手册与已知问题，不提交媒体、截图、数据库或密码。
