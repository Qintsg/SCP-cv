# Data Model: D4 大屏实机收敛

本轮优先复用 005 的实体；只有现场复现证明既有字段不足时才新增数据库迁移。ControlHost 仍是业务库唯一写入者，验证脚本不直接改生产表。

## 大屏播放会话（现有 `PlaybackSession`）

- **身份**：`WindowId` 仅 1/2；保留历史 3/4 行供审计但不执行。
- **状态**：期望源、实际源、`PlaybackState`、`PlaybackMode`、页码/进度、目标显示器、desired/observed generation、最后 Worker 心跳和错误。
- **验证关系**：每次现场截图必须能关联窗口号、命令 generation 和实际进程身份；`playing` 仅是状态证据，不能单独证明画面出帧。
- **约束**：启动、重启、停止后分别核对归属明确的两个、两个、零个播放器；显示器设备名必须是批准的大屏输出。

## 墙面布局（现有 `RuntimeState` 草稿及固定预设）

- **草稿**：输入类型、IP（如适用）、左/右/全屏区域、可应用性及拒绝原因。
- **活动状态**：当前固定预设与最近一次成功实体下发分开；未知组合不得修改活动预设。
- **转换**：保存草稿不产生硬件副作用；仅识别为两个已知固定预设时才允许实体应用。实体失败保持旧活动状态。

## 媒体源与文件夹（现有 `MediaSource` / `MediaFolder`）

- **源**：类型、URL/本机路径、原件路径、名称、文件夹、可用性、摘要、版本、预热意图。
- **目录**：父目录和名称组成媒体根下的实体相对路径，禁止越界、保留名与循环；同名不覆盖。
- **直播源**：优先沿用 `MediaSource` 的 `rtsp_stream`、`srt_stream`、`custom_stream` 枚举，不新增另一份源表作为应用唯一真相。登记表示配置有效、可尝试连接；在线/成功必须来自实际探测或播出观测，不能由登记动作直接推断。
- **移动**：正在播出或转换中的受管理原件不得移动；移动前后原件摘要一致，源 URI 与文件系统路径同步。删除若文件占用，应明确失败或进入可诊断待清理态，不可先丢记录再吞失败。

## 文稿准备作业（现有 `MediaPreparationJob` / `ArtifactManifest` / `PptResource`）

- **身份**：作业 ID、源 ID、源版本与原件摘要；页图制品按源 ID/摘要绑定，与原件所在用户文件夹解耦。
- **状态**：`queued → running → succeeded/failed/uncertain`；中断不盲目重复 Office 外部副作用。
- **发布条件**：页数和有序 PNG 文件完整、摘要一致且原件版本未变化；数据库提交结果不明时先核对清单再补偿文件操作。
- **播放条件**：默认仅 `succeeded` 的页图可打开；实验性原生放映独立受持久设置门禁，关闭后只影响后续打开。

## 运行组及验证记录

- **运行组**：进程角色、PID/启动时间、group/host epoch、准备状态和停机结果沿用既有持久记录；本轮不新增第三、四播放器。
- **验证记录**：正式结论写在 `verification.md`；大体积截图、日志、摘要清单和采样 CSV 保存在 D4/本机 `.validation/`，不进入 Git。每条证据记录提交、时间、窗口、源、预设、进程身份、实际画面观察及是否通过。
- **恢复状态**：测试前保存服务、墙面和系统音量可读状态；测试结束协作关闭 Worker，再停止 ControlHost/前端。电视电源只有切换没有读回，本轮不操作。
