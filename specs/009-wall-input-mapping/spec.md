# Feature Specification: 大屏输入组合与逆向协议接入

**Feature Branch**: `main`（保留当前未提交工作，不切换分支）
**Created**: 2026-10-09
**Status**: Approved
**Input**: 用户要求窗口1/2任意左右、全屏组合，笔记本按输入IP81绑定，并接入已恢复的相关协议。

## User Scenarios & Testing

### User Story 1 - 三种输入任意组合 (Priority: P1)

现场操作者选择窗口1、窗口2或笔记本/IP81，在左右区域或全屏显示；同一输入可同时用于左右。

**Why this priority**: 完成005中只有草稿的手动映射能力。
**Independent Test**: 三种全屏和九种左右组合均能保存、生成正确控制计划及应用；空白半墙清除旧映射。
**Acceptance Scenarios**:

1. **Given** 输入1、2、IP81已绑定，**When** 应用1|2、2|1、1、2、1|1、2|2、IP81|1、IP81|2、1|IP81、2|IP81、IP81、IP81|IP81，**Then** 每个区域使用正确输入及完整源画面。
2. **Given** 旧两个预设，**When** 使用兼容入口，**Then** 既有控制包保持一致。
3. **Given** 仅左或右区域有输入，**When** 应用，**Then** 未映射区域不保留旧画面。

### User Story 2 - 正确发送与真实结果边界 (Priority: P1)

维护者配置实际设备的发送方式，操作者能区分模拟、控制帧发送和状态确认。

**Why this priority**: 防止编码正确但选错配置、乱序或假报成功。
**Independent Test**: 包级向量、回环发送和失败注入验证不同配置、完整阶段顺序及错误状态。
**Acceptance Scenarios**:

1. **Given** 有效配置，**When** 应用布局，**Then** 根据配置选择协议，清屏、映射、提交、刷新顺序正确，同节点多帧不乱序。
2. **Given** 配置无效或流描述缺失，**When** 应用，**Then** 在任何网络写入前拒绝。
3. **Given** 发送中途失败或取消，**When** 返回结果，**Then** 不宣称墙面未变化或完整应用成功，提示状态不确定，不自动重新应用布局。
4. **Given** 收到设备状态，**When** 解析，**Then** 区分帧变体及所属节点，不把旧状态当作当前操作完成证明。

### User Story 3 - 控制台与持久状态一致 (Priority: P1)

操作者看到已保存草稿、已发送布局及明确的确认状态；窗口2全屏不会被旧单屏静音规则误伤。

**Why this priority**: 新输入布局不能继续投影成单/双屏。
**Independent Test**: 公开接口、重建服务读取及真实浏览器核对保存、应用、失败和更换输入。
**Acceptance Scenarios**:

1. **Given** 已应用2或IP81，**When** 刷新页面或重建服务，**Then** 不显示为窗口1全屏，草稿与已发送布局分别呈现。
2. **Given** 同一输入左右重复，**When** 应用，**Then** 两个墙面窗口有独立标识，不增加播放器或占用控制桌面。
3. **Given** 保存后修改选择或另一客户端更新草稿，**When** 应用旧版本，**Then** 拒绝过期请求，未发送当前界面之外的布局。

### Edge Cases

- 全屏与左右互斥、重复区域、空布局、无效IPv4、缺少端口/源尺寸均拒绝。
- 仅支持现有均匀10列5行墙；拼缝、异构节点、特殊型号条件不明确时不猜测。
- 同源左右使用独立墙面窗口，但共享同一输入描述和播放器。
- 数据库提交失败可能已发生设备动作，不能回滚措辞冒充物理回滚。
- 发送中重启标不确定、不重放；不确定标记也无法写入时保留原失败。旧预案不承载手动布局，捕获时该项保持unset。
- 默认不启用加密或猜测设备配置；密钥不进入版本库、接口响应和日志。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 支持三种全屏、九种左右组合以及单侧显示，保留两个旧预设。
- **FR-002**: 笔记本 MUST 默认绑定现场输入IP81，绑定信息由维护配置明确提供，不根据名称猜测媒体地址。
- **FR-003**: 系统 MUST 校验输入地址、端口、源尺寸及发送配置，未知输入/型号能力不得下发。
- **FR-004**: 系统 MUST 按区域产生正确的逐节点目标及源裁剪，窗口标识、层级、窗口数量和屏幕序号分开计算。
- **FR-005**: 系统 MUST 保持阶段屏障、同节点多帧顺序及整体切换排他；取消和失败不得继续提交残缺映射。
- **FR-006**: 系统 MUST 区分草稿、已发送意图、模拟及未确认/不确定状态，不把网络写入当作画面确认。
- **FR-007**: 系统 MUST 保存已发送布局及草稿版本，并根据实际使用的播放器输入决定静音；仅占用既有两块输出。
- **FR-008**: 系统 MUST 拒绝过期草稿应用，前端显示服务端能力和结果而不是自行判断仅两个预设可用。
- **FR-009**: 系统 MUST 支持已恢复且配置明确的映射格式及可选加密传输，解析设备窗口状态；查询触发未确认时明确标记未确认，不杜撰ACK。
- **FR-010**: 文档 MUST 说明配置、原协议证据、已验证组合、未执行现场验收及自定义IP流兼容限制。

### Key Entities

- **输入绑定**：输入身份、单播/组播地址、端口、源分辨率及分类端口。
- **布局草稿**：名称、区域到输入的映射、修订号。
- **发送记录**：本次布局快照、修订号、模拟/已发送/不确定状态与诊断信息。
- **节点状态**：所属连接节点、窗口输入、矩形及层级，不自动等同当前发送的完成回执。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 12种明确组合和6种单侧组合在本地合同及控制计划测试中全部通过，旧预设400包保持一致。
- **SC-002**: 无效输入/配置、过期草稿及未支持能力在测试中100%于网络写入前拒绝。
- **SC-003**: 多帧、并发切换、失败及取消回归无阶段越界、同节点乱序或虚假完成。
- **SC-004**: 桌面和窄屏浏览器均能保存/应用/刷新上述布局，无新增控制台异常；模拟结果明确标注。

## Assumptions

- 用户2026-10-09明确授权通用协议接入；本规范替代005 FR-005对本轮已恢复且受限布局的永久阻止逻辑，但不把逆向差分称为现场验收。
- IP81暂按用户指定绑定，目录提供192.168.5.81、224.1.1.81:5000、3840×2160；现场信号身份仍须出画核对。
- 本轮实施与本机软件验证；不自动开关电源或改变现场墙面，现场抓包/出画验收单独记录。
- 保留任意IP流草稿；缺少明确描述的流不启用，普通RTSP/SRT经窗口1/2播放不受影响。
- 不接入KVM、固件升级、原软件授权体系及未证实型号条件的扩展帧。
