# Feature Specification: 网页屏幕共享到两个播放窗口

**Feature Branch**: `main`（沿用当前工作区，不自动新建分支）

**Created**: 2026-10-10

**Status**: In Progress

**Input**: 用户要求网页端直接发起屏幕共享，选择窗口1或窗口2，像直播但无需额外推流软件；方案自行确定，不提问，完成后测试。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从浏览器共享到指定窗口 (Priority: P1)

操作员在网页选择窗口1或窗口2，点击共享，使用浏览器的原生选择器选取屏幕、应用窗口或标签页；共享的画面在指定播放窗口实时显示，不安装或操作额外推流工具。

**Why this priority**: 这是本次功能的核心用户价值。

**Independent Test**: 桌面浏览器共享包含动态标识的测试内容，逐一投到两个播放器，核对目标实际运动画面和另一窗口不受影响。

**Acceptance Scenarios**:

1. **Given** 已登录且窗口1在线，**When** 确认分享一个测试窗口，**Then** 窗口1显示对应实时内容，窗口2原内容保持。
2. **Given** 已登录且窗口2在线，**When** 确认分享另一个测试窗口，**Then** 窗口2显示正确内容，支持两个窗口同时来自独立共享会话。
3. **Given** 浏览器弹出选择器，**When** 取消或拒绝权限，**Then** 不切换播放器、不产生残留分享、不把失败显示为已共享。
4. **Given** 页面没有安全访问环境、浏览器不支持采集或播放器离线，**When** 查看共享入口，**Then** 明确说明限制及可行的访问方法，不假装已启动或自动绕过权限。

### User Story 2 - 停止、切换及异常后安全回收 (Priority: P1)

操作员能显式停止共享；浏览器自己的停止分享、页面离开、连接丢失、播放器关闭及切换源均能结束对应分享，释放采集和连接。

**Why this priority**: 不泄漏屏幕内容、不误关后来切换的内容，是稳定使用所必需。

**Independent Test**: 连续十轮启动/停止或换源，交错两个窗口；终止后观察播放器、浏览器采集轨道、连接和会话登记的释放。

**Acceptance Scenarios**:

1. **Given** 共享正在进行，**When** 在网页或浏览器停止分享，**Then** 本地采集停止，目标不继续显示冻结的共享画面，另一窗口不变。
2. **Given** 旧分享与新源切换交错，**When** 旧分享的结束消息迟到，**Then** 不能关闭新源或新分享。
3. **Given** 分享者或播放器断线，**When** 超过有限清理时限，**Then** 分享终止并可明确重试，不自动恢复采集或重放。
4. **Given** 同一窗口正在被其他分享者占用，**When** 另一网页尝试启动，**Then** 明确拒绝争抢，不悄悄替换原分享。

### User Story 3 - 清晰状态与可选音频 (Priority: P2)

网页展示采集、连接、实际接收和失败的不同状态；选择内容支持音频且操作员同意时可以共享内容音频，不自动获取麦克风。

**Why this priority**: 防止把控制成功当作大屏已出画，方便现场定位浏览器和网络限制。

**Independent Test**: 验证成功、无音轨、权限拒绝、网络故障、停止待确认，核对真实接收及界面提示。

**Acceptance Scenarios**:

1. **Given** 请求已受理但没有实际帧，**When** 查看状态，**Then** 页面不得显示已出画。
2. **Given** 浏览器未提供内容音轨，**When** 共享画面，**Then** 画面可正常共享，页面明确无音频，不编造音频能力。
3. **Given** 使用窄屏或键盘操作，**When** 查看并控制会话，**Then** 目标、主要操作和错误提示可达，保持既有主题及可见焦点。

### Edge Cases

- 用户在系统选择器中长时间停留；选定后服务启动失败，采集须释放。
- 浏览器仅支持部分共享内容音频；不请求麦克风作为替代。
- 两个窗口同时共享；状态和停止必须按会话身份隔离。
- 已登出的客户端、错误会话、过期会话、恶意超大信令；不得注入或读到其他人的共享。
- 打开分享后立刻停止、重复停止、旧应答或旧网络回调迟到。
- 控制服务或播放器重启；旧会话不可自动继续采集或恢复播出。
- 网络连接成功但没有新帧；不以心跳或连接状态冒充实际显示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 从网页端原生发起屏幕/窗口/标签页共享，目标仅窗口1或窗口2；不用额外推流应用或手工配置直播源。
- **FR-002**: MUST 保持浏览器的明确用户授权，不后台采集；取消/拒绝不切换源，服务失败后释放已取得的采集。
- **FR-003**: MUST 支持两个独立目标同时共享，限制每目标一个活动会话，另一播放窗口及控制桌面保持不受影响。
- **FR-004**: MUST 支持网页停止和浏览器停止，页面销毁/异常/断线在有限时间内回收；不得自动重试采集、切换或播放。
- **FR-005**: MUST 用会话身份与源代次围栏处理结束、换源和迟到回调；旧分享不得清理后来内容。
- **FR-006**: MUST 沿用登录/请求防伪边界，分享与接收只向获授权会话开放；信令及状态有界，停止/超时撤销会话，不持久保存或录制屏幕媒体。
- **FR-007**: SHOULD 在浏览器提供内容音轨且用户同意时一起共享；没有音轨仍共享视频，明确说明音频实际能力，不请求麦克风。
- **FR-008**: MUST 显示采集/连接/实际接收/失败/停止待确认等状态；指令受理、连接成功或心跳不得当作已出画。
- **FR-009**: MUST 提供支持浏览器与安全访问方式的检查及说明，不依赖关闭浏览器安全策略；局域网访问的部署配置与证书要求有文档。
- **FR-010**: MUST 复用现有两窗播放与控制台，保持媒体源、墙面映射、电源和普通播放不变；新增代码合理解耦。
- **FR-011**: MUST 完成自动化安全/生命周期回归、真实浏览器采集与传输、两个真实播放器实际运动画面及重复停止切换测试，分层记录证据和未验证边界。

### Key Entities

- **分享会话**: 会话身份、所属操作员、目标窗口、源代次、生命周期、有效期及实际接收证据。
- **采集资源**: 用户授权的屏幕视频、可选内容音轨及本地浏览器连接，寿命绑定分享会话。
- **目标接收者**: 指定播放窗口的独占接收资源，与分享身份绑定，不扩大为新的播放窗口。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在支持的桌面浏览器及同一局域网内，用户授权后20秒内指定窗口出现可辨别的动态测试内容；分别验证窗口1和窗口2，非目标画面保持。
- **SC-002**: 十轮启动/停止与交错换源后，无遗留采集、活动分享或误关其他内容；显式停止后10秒内停止显示共享，断线后30秒内终止。
- **SC-003**: 两个不同分享会话同时运行至少5分钟，目标标识正确、动态画面继续变化，分别停止不会影响另一窗。
- **SC-004**: 所有取消、拒绝、离线、不支持、会话争抢及未授权测试明确失败，未产生意外播放或假报实际出画。
- **SC-005**: 桌面与390px窄屏主要操作可达，无横向溢出；键盘能选择目标及停止，用户可区分请求受理与实际接收。

## Assumptions

- 首版面向同一现场局域网内支持原生分享的桌面浏览器；手机端和不支持采集的封装端明确禁用，不伪装支持。
- 默认只分享画面；音频由用户选项及浏览器实际返回轨道决定。不录制，不保存采集内容，不引入付费许可。
- 屏幕分享只改变选定播放器的内容，不改变墙面分区或设备电源；画面如何映射至墙面仍由既有功能决定。
- 安全访问的证书信任需要在访问设备配置；不得以关闭浏览器安全限制作为正常使用步骤。
- 用户授权自行确定方案并完成测试；选用方案的限制与验证结果直接记录，不再请求技术选项。
