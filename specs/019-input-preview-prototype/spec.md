# Feature Specification: 输入选择与预览复用原型

**Feature Branch**: `main`（沿用当前工作区）
**Created**: 2026-10-21
**Status**: Prototype in progress
**Input**: 用户要求先给小demo：其他输入的可搜索／滚动二级菜单、工作站目录、窗口3/4预览、前端已取流复用、修改比例不全量重连和更快首帧。随后以设备表修正IP，75不存在，76仅监控。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 选择更多输入 (Priority: P1)

操作者在原有单屏／双屏／自定义布局中选择窗口1–4、IP81或“其他输入”，按名称与IP末段找到工作站／摄像机。

**Why this priority**: 先确认新增选源的操作形态，不直接改现场控制。
**Independent Test**: 本机原型可切换三种选源展开方式，滚动／搜索并在本地改变对应布局块。
**Acceptance Scenarios**:

1. **Given** 输入列表，**When** 打开其他输入，**Then** 能搜索名称／末段IP并滚动，IP只显示IP51这类末段形式。
2. **Given** 用户最新表格，**When** 查看目录，**Then** 工作站为D1-1至D6-4、IP51–74共24路，75不存在；76仅监控01，81现场，84后、85中1、86中2、87左、88右。
3. **Given** 窗口3/4，**When** 选择，**Then** 本地预览分别对应65/66；不创建.NET窗口。

### User Story 2 - 浏览工作站目录 (Priority: P2)

操作者在媒体源式目录中查看工作站和Camera，筛选模拟可达输入，将选中项放入目标区域。

**Why this priority**: 确认目录和选源共用同一设备命名，避免重复维护或错配。
**Independent Test**: 切换目录／模拟状态筛选／名称搜索，选择后只影响明确目标。
**Acceptance Scenarios**:

1. **Given** 工作站目录，**When** 只看可达，**Then** 显示夹具中的模拟可达项并标注数据为演示，不声称现场已探测。
2. **Given** 同一设备有窗口和工作站别名，**When** 查看详情，**Then** 指向相同的规范输入和组播示意，监控不混入工作站。

### User Story 3 - 改布局而不中断已有预览 (Priority: P1)

操作者调整布局比例或重用已有输入，现有画面持续播放；只有真正换源才新增或释放对应演示流。

**Why this priority**: 演示源身份与布局几何解耦后的连续性。
**Independent Test**: 本地生成动态画面，多个video实际共用一个演示源，观察连接／复用计数与首帧标识。
**Acceptance Scenarios**:

1. **Given** 已有窗口3的演示流，**When** 选D4-3，**Then** 共用IP65的源，不新增生产者。
2. **Given** 正在播放的区域，**When** 只改比例／位置，**Then** 保持视频对象和演示源，播放时间继续，不重置全部画面。
3. **Given** 首帧数据，**When** 展示指标，**Then** 仅标“本地演示首帧”，不得声称RTMP网络性能已优化。

### User Story 4 - 摄像机、电视和预案 (Priority: P1)

摄像机页展示当前所选预览，按CameraBOX参考核对方向／变焦／预置位语义。仪表盘增加电视左／右，每台单路输入、选项同大屏；预案可分别保持或设置大屏和电视。原型用内存记录模拟上次下发，预案相同跳过、仪表盘允许手动重发。预览以1px绿／黄／红边框表示已出帧／重连／失败，去掉常驻提示和性能文字，诊断折叠。

**Independent Test**: 窗口3和D4-3规范键一致；摄像机页仅一个当前预览，固定监控无云台；两电视可独立选源；模拟预案同一输出不变跳过，几何变化不被相同IP掩盖，未知状态不得跳过。颜色之外有辅助技术状态／悬浮原因，不堆常驻文字。

正式服务端持久记录、TV专有帧与预案集成、真实源发现和摄像机实测属于确认原型后的实施，不把内存模拟称服务端已完成。

### Edge Cases

- 75及用户表格空端口不自动生成；76只出现监控身份。
- 模拟离线不允许伪装可用；没有匹配项有明确空态。
- 改选源、切变体、删除块、隐藏页面与退出后有所有权明确的演示资源清理。
- 不同清晰度对应不同实际通道时不能无条件合并；原型只演示同一规范演示流的复用。
- 组播IP沿既有224.1.1.末段惯例仅作示意，不在本轮验证或下发设备协议。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 提供本机可交互原型，沿用Vue／Ant现有视觉语义，三个结构不同的选源变体可由URL切换。
- **FR-002**: MUST 提供其他输入的二级入口、滚动、搜索、明确当前选择与无结果状态。
- **FR-003**: MUST 按最新表格呈现24工作站、6摄像机／监控及81现场输入；65/66具备窗口3/4别名，不包含75。
- **FR-004**: MUST 演示工作站目录、筛选和向目标区域选源；连通状态仅为明确标识的内存夹具。
- **FR-005**: MUST 用实际本地动态媒体演示同源共享及几何变更不重建；提供可观察的生产者、消费者与重建计数。
- **FR-006**: MUST 将首帧指标限定为本地演示，不声称真实RTMP／FLV已优化；正式首帧和浏览器共享池留待原型确认后的生产实现。
- **FR-007**: MUST 不访问D4／设备／业务API，不写数据库，不推送或部署；仅监听本机回环，构建不将原型加入生产路由。
- **FR-008**: MUST 将CameraBOX作为只读参考核对现有协议，原型摄像机页可选择对应预览，固定监控不显示可用云台。
- **FR-009**: MUST 原型包含两电视单路选源及预案分别配置／模拟去重；不冒称TV真实协议或服务端持久化已接通。
- **FR-010**: MUST 预览仅用细绿／黄／红边框表现状态，去除常驻连接／复用／首帧提示，必要诊断折叠。

### Key Entities

- 输入目录项：规范IP末段、设备名称、别名、类别、模拟连通状态及组播示意。
- 布局块：稳定身份、来源身份、50格中的几何位置；几何不参与来源共享键。
- 演示流：规范输入唯一的本地动态媒体生产者及消费者计数，无网络上游。

## Success Criteria *(mandatory)*

- **SC-001**: 原型三种选源方式可独立打开；搜索65能定位D4-3／窗口3，工作站数24、75出现数0、76为监控。
- **SC-002**: 多处使用IP65时生产者只1个；只改变布局几何时新建／关闭演示源增量均0，原视频播放时间连续。
- **SC-003**: 常用桌面及手机宽度没有横向溢出，二级长列表可滚动，搜索和当前选择可辨认。
- **SC-004**: 网络观测中现场IP请求／业务写入均0；演示／非实时数据边界可见，未更改D4部署。

## Assumptions

- 用户要求先看小demo，本轮不实现真实连通探测、正式客户端共享池、FFmpeg首GOP优化或实体映射。
- D1-1…D6-4与51–74顺序严格对应；76监控01、81现场、84–88摄像机以最新表格为准，不再推断D7或75。
- 深色／浅色沿既有Ant控制台，采用独立本机演示入口以避免生产Shell初始化鉴权或连接D4；此隔离优先于嵌入真实仪表盘。
