# Feature Specification: 播放恢复与摄像机低延迟

**Feature Branch**: `main`
**Created**: 2026-10-21
**Status**: 已恢复当前功能；原始运行组退出原因待调查
**Input**: 修复背景音乐错误、当前视频和PPT无法打开，降低摄像机延迟，并依据当前全局AGENTS规范检查并修正仓库约定。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 视频和演示文稿正常打开（Priority: P1）

操作者在D4选择现有视频或演示文稿后，播放窗口能够显示实际内容，并可以切换与关闭。

**Why this priority**: 当前媒体无法使用。
**Independent Test**: 使用真实现有文件，在D4窗口完成打开、切换、关闭和重复打开，检查实际播放进度、文稿页数和进程退出。
**Acceptance Scenarios**:
1. 有效视频能显示实际帧、播放进度持续增加，停止后释放媒体资源。
2. 有效PPT通过现有文稿引擎显示页内容，翻页和关闭可完成。
3. 文件缺失、依赖失败、输出绑定失败时立即报告具体原因，不报告播放成功。

### User Story 2 - 背景音乐状态与实际运行一致（Priority: P1）

运行组正常启动后，背景音乐页面正确显示当前状态；遇到故障时保留对应实际故障，恢复成功后显示可用状态。

**Why this priority**: 当前错误影响正常操作和故障判断。
**Independent Test**: 使用真实音频和运行组，验证正常启动、播放/停止、协作重启与状态恢复，不改变其它应用音频设置。
**Acceptance Scenarios**:
1. 当前运行组有效且没有背景音频来源时显示停止状态，历史进程退出提示不持续覆盖当前状态。
2. 真正的依赖或播放故障仍可诊断，恢复必须有当前进程和实际状态证据。
3. 默认输出设备、音量、用户列表和原媒体引用保持。

### User Story 3 - 摄像机画面及时更新（Priority: P1）

摄像机预览和播放保持按需共享，同一来源可以及时显示当前画面，网络恢复后不会持续显示积压画面。

**Why this priority**: 当前延迟影响现场监看。
**Independent Test**: 对相同输入记录修改前后的首帧及软件附加延迟，使用实际摄像机和真实编码/解码过程核验；持续运行和断开恢复后检查共享数量与资源释放。
**Acceptance Scenarios**:
1. 记录当前服务转发、编码、客户端缓冲各环节的延迟证据，按原因修改。
2. 降低软件可控制的延迟，保持可解码画面和受限资源使用。
3. 观看者没有请求时停止拉流；相同来源的多个预览继续共享。

### User Story 4 - 仓库约定符合当前全局规范（Priority: P2）

维护者按照仓库文档执行命令、修改代码和验证功能时，操作约定与最新全局指引一致。

**Why this priority**: 避免维护命令和验证说明互相冲突。
**Independent Test**: 检查当前AGENTS、开发文档、包管理命令、本轮修改的文件头和错误处理，并执行修订后的命令。
**Acceptance Scenarios**:
1. 使用用户最新指定的包管理工具，文档与实际脚本一致。
2. 本轮新增和修改代码包含所需文件头；错误可以被定位，验证使用实际文件/服务/进程。
3. 修改依据当前文件内容，保留用户已有变更，不修改全局AGENTS文件。

### Edge Cases

- 运行组更换后收到旧进程的退出通知；当前来源为空或真正播放失败。
- 两个窗口同时打开、快速切换、关闭期间资源仍在释放。
- 已有原生媒体进程、播放依赖不完整、编码器输出4K及CPU负载过高。
- 摄像机主/子通道不同、网络中断、观看者重复连接、页面隐藏或退出。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 定位D4视频/PPT打开失败的实际错误并修复，维持两原生窗口限制和现有输出绑定。
- **FR-002**: MUST 基于当前运行组身份和真实音频状态处理背景音乐恢复，历史故障不得持续覆盖已恢复状态。
- **FR-003**: MUST 对实际未恢复的故障明确失败，不通过吞掉错误、替换成功状态或更换测试内容隐藏问题。
- **FR-004**: MUST 测量并降低摄像机的软件附加延迟，保留同源共享、按需拉流、访问控制和资源限制。
- **FR-005**: MUST 同时验证实际媒体打开、切换、关闭和故障恢复，检查资源释放，使用真实文件与实际进程。
- **FR-006**: MUST 核对最新全局AGENTS与当前项目约定，修正本轮涉及的命令、注释及验证说明。
- **FR-007**: MUST 更新相关文档和配置说明；公开接口变化同步OpenAPI并校验。
- **FR-008**: MUST 保留D4媒体、预案、声音配置、当前系统显示模式及当前合法播放意图；保留软件4K支持。完成测试后保持用户最新操作结果，不回放旧快照；不得操作墙面映射、电源或云台。

### Key Entities

- 当前运行组：身份、代次、实际进程与退出原因。
- 媒体执行结果：来源、命令、实际输出、失败原因和释放状态。
- 预览延迟证据：输入、时间、通道、编码方式、缓冲与画面进度。

## Success Criteria *(mandatory)*

- **SC-001**: D4真实视频/PPT各完成至少5轮打开、切换和关闭，无未解释失败或残留自有媒体进程。
- **SC-002**: 背景音乐真实播放/停止及正常运行组恢复后，界面状态与当前进程和媒体状态一致；实际故障可重复检出。
- **SC-003**: 相同受控输入的软件附加延迟相对基线降低至少30%，记录实际摄像机结果及连续运行/恢复情况，不把无法量测的采集延迟标为通过。
- **SC-004**: 最新规范要求涉及的命令和本轮代码检查完成，相关实际验证通过，配置和媒体引用保持。

## Assumptions

- 允许在本机及D4执行本请求所需的媒体播放、关闭、服务更新与重启验证，保留原播放快照；不扩大到实体设备控制。
- 保持当前全局AGENTS原文件，只修改仓库中需要调整的约定和实现。
- 不使用computer use；可通过API、日志和只读无头浏览器检查实际媒体/页面，不模拟用户输入。
- 优先使用现有真实测试资源，不覆盖用户文件，不将媒体或凭据提交仓库。
- 本轮部署前快照与10:38UTC复核均显示DISPLAY2–5及输入63–66为1920×1080；系统模式保持该实际值。先前4K记录不作为本轮当前状态证据。
- 用户追加显示模式回退的诊断要求；本轮只读调查当前显示描述、保存模式和驱动事件，不自动修改Windows模式、EDID或驱动。切换触发的受控复现与维护验证按T022记录，未完成时不得认定已修复。
