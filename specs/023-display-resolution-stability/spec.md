# Feature Specification: D4四路4K模式稳定性

**Feature Branch**: `main`
**Created**: 2026-10-21
**Status**: 调查中
**Input**: 查明D4显示器2–5分辨率回退及1–5横向位置被覆盖的原因，消除确证触发条件；不使用自动恢复。

## User Scenarios & Testing

### User Story 1 - 四路输出使用4K（Priority: P1）

现场操作者使用D4的显示器2–5时，桌面及设备实际接收的信号均为3840×2160，控制桌面、媒体和声音保持。

**Why this priority**: 大屏映射使用实际输入尺寸。
**Independent Test**: 同时核验系统桌面、输出信号及63–66的主组播输入读回。
**Acceptance Scenarios**:
1. 对明确设备设置4K后，四路均实际生效，控制桌面保持。
2. Windows拒绝配置或实际信号没有生效时明确失败。

### User Story 2 - 消除回退触发原因（Priority: P1）

操作者希望分辨率在正常使用中保持4K，能够知道导致回退的具体组件及处理依据。

**Why this priority**: 自动重设无法消除驱动、显示识别或外部程序导致的异常。
**Independent Test**: 取得回退瞬间和触发组件的证据；针对已确认原因处理后，重复原触发动作并验证不回退。
**Acceptance Scenarios**:
1. 区分Windows桌面尺寸、实际信号、显示描述、保存配置及显卡故障，不能混为同一证据。
2. 核对新近TDR、外部显示设置动作和远程软件记录，不能只按同时安装的软件认定责任。
3. 不部署自动改回4K的常驻任务，不通过重复写入掩盖问题。

### Edge Cases

- 驱动超时或显示设置调用阻塞；用户手动修改模式和排列；远程软件调整输出。
- EDID仅报告1080p，但驱动允许自定义4K；桌面4K而实际信号不同。
- 设备重连、模式重新建立、私有诊断数据缺失。

## Requirements

- **FR-001**: MUST 核验四路真实4K，保护控制桌面、当前媒体与业务进程。
- **FR-002**: MUST 定位触发回退的实际组件与动作，保留可复核的时间和设备身份。
- **FR-003**: MUST 不使用回退后自动设置分辨率的常驻恢复方案。
- **FR-004**: MUST 对显卡、远程软件和显示描述进行有证据的排查，未复现的根因如实保留。
- **FR-005**: MUST 在根因明确后按授权范围处理并复验；需要重启Windows或调整实体输入设备时先明确影响和所需授权。
- **FR-006**: MUST 同时比较原生活动布局、CCD持久布局和GDI保存模式，区分分辨率降低与位置覆盖；捕获变化前后的设备路径和调用进程身份。

## Success Criteria

- **SC-001**: 四路桌面和实际输入均为3840×2160，控制桌面及用户媒体保持。
- **SC-002**: 取得能够归因回退的具体证据，重复触发动作后不再回退。
- **SC-003**: 没有自动重设分辨率的后台任务，未知原因不会标记已修复。
- **SC-004**: 位置核验以024的1–5连续横向排列为目标；覆盖发生时能区分活动配置和保存配置的变化，不通过自动写入恢复位置。

## Assumptions

- 可执行相关只读诊断和已授权的显示模式设置；不主动触发GPU故障或重启Windows。
- 不使用computer use；现场其它软件、媒体及原一键启动保持。
- 用户明确允许临时停止D4的UU远程进行对照复测，允许中断该远程连接；保持SSH、网页和播放服务，测试后恢复UU远程原服务配置与启动状态。
