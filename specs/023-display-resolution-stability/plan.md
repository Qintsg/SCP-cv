# Implementation Plan: D4四路4K模式稳定性

**Branch**: `main` | **Date**: 2026-10-21 | **Spec**: [spec.md](spec.md)

## Technical Context

Windows10 18363、NVIDIA A4000/537.70、四个CRA2400目标、ASPEED控制桌面。以成熟DisplayConfig6.0.0组件读取实际桌面及目标信号，使用现有611A只读工具核对输入。诊断证据保存在本机忽略目录，不公开私有应用配置或内核数据。

## Constitution Check

保留真实硬件验证、当前用户意图和明确错误。业务API、数据及播放器限制保持。没有未经授权的驱动、实体设备或系统重启变更；未知根因不报告解决。

## Investigation

核对回退时间附近的Windows事件、显卡重置、显示识别和远程软件的具体模式设置记录，区分用户手动设置与系统变化。只读取得当前及推荐时序、EDID身份与保存配置。遇到阻塞的自有诊断进程时核验PID/启动时间/会话/路径，停止后确认实际退出；无法退出如实记录，不扩大结束范围。

具体处理取决于归因证据。系统级或实体输入设备配置变更前明确影响，采用原触发动作验证稳定性。交付前核对四路实际输入、原业务进程与声音，更新维护和输入尺寸记录。

2026-10-23继续调查分辨率与位置：以024的实际横向排列为基线，使用PowerShell7和独占Job取得有界活动、CCD持久及GDI当前/保存配置。事件采集具备有限时间、8MiB缓冲及64MiB环形文件；首尾自有ETW事件用于核验采集链路。先以SDC_VALIDATE验证当前配置，再独立执行一次内容完全相同的SDC_APPLY以检查真实提交事件；提交前核对五屏及设备路径，配置有变化就停止，不使用SAVE、强制驱动重设或自动恢复。对显示注册表写入事件保留进程、线程、值名和时间，联合独立配置读回归因。

当前CV测试许可覆盖正常媒体对照：仅当两窗空闲在线、窗口2已静音时，在窗口2顺序打开原视频91与LibreOffice文稿90，记录原进程、实际进度及显示状态；每种来源关闭后回到空闲，窗口1和声音配置保持。ETW单次150秒，Job上限512MiB及175秒；不施加GPU故障或压力，不提交Windows模式。来源或代次被其他操作者改变时停止关闭。

间歇问题使用一次限时实时记录：首先实际验证10秒采集及完整退出，再手动启动最长一小时的隐藏交互任务，无登录或周期触发器。只订阅显示模式和显示注册表事件，首次提交后继续45秒以覆盖延迟写入，保存活动与持久配置前后状态后结束并删除自身任务；无事件时到期结束。原生Job上限512MiB、事件文件上限64MiB，进程优先级BelowNormal。记录器没有Windows显示写入API，不进行任何自动恢复。

## UU远程对照复测

记录当前服务启动方式、路径、进程身份、四路611A、Windows尺寸和业务状态；在只读ETW采集期间正常停止GameViewerService，再核对其安装目录内的所属进程是否退出。只结束本次快照核验的UU进程，保持其它远程工具、虚拟显示驱动与业务进程。停止阶段和重新启动阶段分别取得实际尺寸与事件。无论验证结果如何，都通过finally恢复原服务及必要的交互客户端；失败明确报告，不把未回退当作已排除。观察期间不提交Windows显示模式设置。
