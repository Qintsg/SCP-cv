# Feature Specification: 大屏帧尺寸纠正与现场分辨率核验

**Feature Branch**: `main`
**Created**: 2026-10-21
**Status**: Implemented locally（未部署；实体出画未验）
**Input**: 用户报告当前大屏布局帧不正确，D4显示器现应均为4K，要求优化并自行探索其它设备分辨率。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - D4四路正确裁剪 (Priority: P1)

操作者选择D4窗口1–4进行单屏、双屏或自定义布局时，源裁剪与当前实际输入一致，不因旧1080参数或未经核验的4K默认值而重复、偏移或缺块。

**Why this priority**: 当前错误直接影响大屏显示。
**Independent Test**: 对照实际输入证据，逐包核对来源、源裁剪和目标矩形；不依赖仅“发送成功”。
**Acceptance Scenarios**:
1. D4桌面和输入源分辨率分别记录，使用映射的实际来源证据，不将桌面4K自动套用到全部参数。
2. 同一输入的窗口别名与设备IP使用同一尺寸，预案与手动布局不产生不同裁剪。
3. 改变输入尺寸时正确重建计划；原输出节点若仍为1080则保持，不把50个目标节点一起盲改4K。

### User Story 2 - 其它输入的可追溯核验 (Priority: P1)

维护者能区分工作站、现场IP81和摄像机的实测、设备声明、工程旧值及离线未知结果，避免错误默认值持续进入控制帧。

**Why this priority**: 020其余输入曾采用工程统一4K声明，尚无实时核验。
**Independent Test**: 固定清单逐项输出设备、链路、时间、尺寸及证据等级；超时、断开与无匹配响应保留独立状态，不把网络失败当已核验尺寸。
**Acceptance Scenarios**:
1. 核验工作站51–74、监控76、现场81、摄像机84–88，不生成不存在的75。
2. 预览主/子码流与实际映射码流不混为同一事实；若只能读取预览，不冒称已证组播尺寸。
3. 探测有时限、并发和流量约束，结束释放自有连接/进程；设备离线不触发电源、云台、配置写入或密码猜测。

### Edge Cases

- 桌面4K但编码器降采样，主/子码流尺寸不同，组播与预览不同。
- 设备离线、SPS缺失、鉴权失败、旧工程与实时结果矛盾。
- 明确管理员配置与自动探测不一致，帧未确认、先前布局记录因尺寸变化失效。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 定位并纠正错误帧的具体尺寸来源，区分桌面、映射源裁剪、目标节点尺寸。
- **FR-002**: MUST 核验D4四路63–66的实际状态；当前4K要求不应继续受旧1080假设影响。
- **FR-003**: MUST 在固定现场清单内进行有界只读分辨率调查，保留每项时间、来源、尺寸和失败原因。
- **FR-004**: MUST 明确区分实际映射流、预览通道、设备声明和工程默认，未知不能标为实测。
- **FR-005**: MUST 使窗口/IP别名、手动布局与预案使用一致的源尺寸；尺寸变化不能错误跳过去重。
- **FR-006**: MUST 保留目标节点及两电视的独立参数，未证实前不随D4源一并改4K。
- **FR-007**: MUST 为修复加入包级/计划回归并更新文档；未执行实体出画时如实说明。
- **FR-008**: MUST 不修改Windows分辨率或设备配置，不新增常驻全流探测，不向未知协议发送猜测命令。

### Key Entities

- **分辨率证据**：设备、角色/链路、像素尺寸、时间、采集方法、证据等级与可用状态。
- **映射尺寸描述**：来源裁剪范围与输出节点目标范围，两者独立。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对31路输入逐项给出核验状态；不存在无说明遗漏或把离线默认为4K。
- **SC-002**: 四路D4及输入别名的全屏/左右/自定义计划在包级测试中使用同一已确认尺寸，源裁剪不越界且分片覆盖完整。
- **SC-003**: 调查期间实体映射/电源/云台/配置写入为0，自有探测资源在退出后归零。
- **SC-004**: 原有布局/电视/预案回归通过；实测与未知结果、未执行现场项均可追溯。

## Assumptions

2026-10-21后续授权：用户要求“推送并部署”，现允许推送两个既有仓库并更新D4运行组及桌面启动入口。保留用户数据和旧包，正常短暂停播/重启纳入部署，不因此授权墙面、电视、电源、云台或音量实测，也不修改Windows分辨率。

- 用户要求修复与探索，先只读调查并在本机实现/验证；本轮不自动推送、部署或向现场下发测试布局，除非用户后续明确要求。
- 允许对清单设备短时读取状态/流描述，必要时取有限媒体数据核验，不中断其它服务。
- 无法核验的设备保留未知和最后可靠证据，不自动用另一设备或低清通道的值代替。
- 已恢复的611A主输入查询不带鉴权，本轮不通过猜测凭据探测预览流；若其它链路需鉴权失败，不据此猜测主组播尺寸。
