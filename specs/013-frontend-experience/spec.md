# Feature Specification: 现场控制台前端体验优化

2026-10-16后续组件库和布局重构以[014](../014-ant-design-console/spec.md)为准。013保留功能安全、请求归属及历史验证要求，不将旧视觉排布作为新Ant界面的限制；014尚未部署。

**Feature Branch**: `main`（沿用当前分支）

**Created**: 2026-10-15

**Status**: Implemented — 人工视觉验收部分待完成（见verification.md）

**Input**: 用户要求暂不处理此前现场验收阻碍，全面优化前端操作体验和表现，并使用“说人话”处理文案。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 快速找到并完成常用操作 (Priority: P1)

现场人员进入控制台后，清楚当前位置、连接状态、两窗口分工，直接进入媒体、播放、声音或预设。

**Why this priority**: 现场操作需要迅速定位，减少重复标题、装饰和技术信息带来的干扰。

**Independent Test**: 首页进入两个窗口、媒体库、摄像机与音量、背景音乐、预设和设置，检查返回、焦点和小屏导航。

**Acceptance Scenarios**:

1. **Given** 任意主要页面，**When** 浏览或使用键盘导航，**Then** 标题、主操作、当前位置和当前导航项一致，跳转后主内容不保留上一页滚动位置。
2. **Given** 首页，**When** 查看运行状态和两窗口，**Then** 可区分连接、播放器在线与当前播放，不把在线当作已出画。
3. **Given** 手机，**When** 切换两窗口或进入次级功能，**Then** 保留可达的底栏和关闭入口，不遮挡主要操作。

### User Story 2 - 像管理文件一样管理媒体和预设 (Priority: P1)

目录路径、搜索、筛选、多选和打开操作有一致的布局与反馈；能够分清目录为空和筛选无结果。

**Why this priority**: 媒体与预设是日常操作的主要入口，当前工具分散且小屏拥挤。

**Independent Test**: 根目录与两层子目录切换、筛选、搜索、清除条件、多选取消及打开小卡片；不向现场设备发包。

**Acceptance Scenarios**:

1. **Given** 当前目录存在文件，**When** 搜索或筛选无结果，**Then** 显示无匹配项及清除条件入口，不能误导为需要上传。
2. **Given** 已选择多个项目，**When** 更改目录或取消选择，**Then** 操作范围和数量明确，不误操作隐藏或受保护项目。
3. **Given** 长名称和多层目录，**When** 在窄屏显示，**Then** 路径和操作可达，长文本不挤出页面。

### User Story 3 - 清楚看到操作结果和限制 (Priority: P1)

播放、共享、摄像机与声音、设置的主要操作有一致的等待、成功、失败、空状态和不可用原因。

**Why this priority**: 改善外观不能掩盖真实运行状态或增加误操作。

**Independent Test**: 本机隔离或仿真数据覆盖在线/离线、忙、只读、部分失败、末页和共享HTTPS限制；确认没有新增自动实体动作。

**Acceptance Scenarios**:

1. **Given** 操作尚在进行，**When** 再次点击或离开页面，**Then** 保留原有防重与迟到响应规则，不因视觉调整重发命令。
2. **Given** 请求只被受理或设备只确认写出，**When** 展示结果，**Then** 明确当前阶段，不写成播放或实体执行成功。
3. **Given** 未配置项或不可用能力，**When** 查看表单，**Then** 说明保持原状或不能操作的原因，不提供无意义的假入口。

### User Story 4 - 各尺寸、主题和输入方式都可用 (Priority: P2)

主要页面统一留白、标题、卡片、工具栏、表单和操作区；明暗主题、触屏、键盘和减少动效偏好均可使用。

**Why this priority**: 现场电脑、笔记本与手机应有一致操作习惯。

**Independent Test**: 360/390/768/1280/1920宽度，明暗主题，键盘焦点、长文案、滚动与抽屉验证。

**Acceptance Scenarios**:

1. **Given** 小屏或200%缩放，**When** 使用主要页面，**Then** 页面不横向溢出，触控操作目标至少44px，表格可在自身区域横向滚动。
2. **Given** 键盘用户，**When** 进入导航、抽屉与表单，**Then** 焦点可见、关闭后回到触发位置，普通导航不自动执行设备动作。
3. **Given** 减少动效偏好，**When** 切换页面和控件，**Then** 不依赖动画传递状态。

### Edge Cases

- 断线、重连、权限不足、请求失败与旧响应；保留原错误，不以空列表覆盖失败。
- 超长文件名、深层目录、内置只读项、多选后切目录、搜索结果跨目录。
- 两窗口不同播放引擎、PPT末页、共享清理中、设备无读回、预设部分配置。
- 窄屏、浏览器缩放、系统暗色、高对比与减少动效。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 覆盖首页、两窗口、媒体库、背景音乐、摄像机与音量、预设、设置、连接和登录页面，保持现有业务入口可达。
- **FR-002**: 建立一致的页面标题、说明、主次操作、内容宽度和状态区域，减少重复品牌头和装饰性占位。
- **FR-003**: 首页提供两窗口当前状态及常用功能的明确入口；状态不能从在线推断出画。
- **FR-004**: 媒体和预设使用一致的路径、工具栏、选择范围与空结果反馈，保留目录、筛选、批量逐项结果及保护规则。
- **FR-005**: 操作反馈用具体对象、动作和下一步说明结果；保留发送/受理/实际完成/未知之间的区别。
- **FR-006**: 主要页面的加载、失败、空、忙、不可用与只读状态完整，危险操作保持确认，不新增隐式设备动作。
- **FR-007**: 360px起主要内容无页面级横向溢出，小屏主要操作目标不小于44px，键盘焦点可见。
- **FR-008**: 明暗主题、长内容和减少动效支持一致；滚动区域与导航切换行为可预期。
- **FR-009**: 使用“说人话”整理用户可见文案，不改接口字段、数字含义、完成状态及限制条件。
- **FR-010**: 用自动化及真实浏览器检查关键页面与流程，记录未执行的环境检查；初轮仅在本机隔离验证。2026-10-15用户追加授权后，将已验证网页部署D4并推送两个仓库，不发送实体控制命令、不重启播放运行组。

### Key Entities

- 页面上下文：标题、说明、当前位置与主次动作。
- 操作反馈：对象、阶段、结果、可重试性及原因。
- 目录视图：当前路径、筛选、搜索、结果数与选择范围。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全部主要页面使用一致的信息层级，首页到任一常用功能最多两次导航操作。
- **SC-002**: 360/390/768/1280/1920宽度检查页面级横向溢出为0；手机主要操作目标均至少44px。
- **SC-003**: 目录无匹配、选择取消、页面切换、危险操作取消和不可用能力都有对应回归；不新增隐式设备写操作。
- **SC-004**: 既有前端回归、类型检查、网页构建及规范校验通过；新增体验行为有独立回归和可审查截图。

## Assumptions

- 沿用当前产品与设计体系，优化整体体验，不另造营销风格或引入新UI框架。
- 本轮不改变协议、权限、双窗/播放/声音/共享生命周期、安全和后端数据合同；旧现场未验项不算本轮前端完成。
- 初轮使用本机隔离数据，保留本地提交；2026-10-15追加授权推送GitHub/GitLab并仅部署D4网页，保留原运行组、数据库、媒体、证书、端口及播放状态。
